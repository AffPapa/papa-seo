# papa-seo — SEO-скил для Claude Code и Codex

Скил для Claude Code и OpenAI Codex: SEO-аудит страницы и сайта под Google, Яндекс и AI-поиск, ТЗ копирайтеру, статьи и рерайт без признаков ИИ.

[English](README.en.md) · [Быстрый старт](QUICKSTART.md) · [Безопасность](SECURITY.md) · [Изменения](CHANGELOG.md) · [Страница проекта](https://affpapa.org/papa-seo)

Это SEO с помощью нейросети, но не онлайн-сервис: скил работает внутри вашего агента, читает живой HTML и ваши выгрузки и к каждому выводу прикладывает доказательство.

- Проверяет страницу одной командой: `python3 scripts/audit.py <адрес>` — два запроса к сайту, HTML-отчёт с очередью «чинить первым». За командой стоит реестр из **415 параметров** в 13 группах: индексация, canonical, robots.txt, sitemap, микроразметка, скорость, мобильность, безопасность, внутренние ссылки, текст. У каждого параметра записано, из чего он считается и есть ли требование в документации поисковика.
- **Советы за требования не выдаёт.** Там, где требования в документации нет, стоит пометка «ориентир редактора» — это наше мнение, а не правило Google; таких параметров 77, и тест-страж не даёт назвать их обязательными. У каждой находки есть цитата из HTML и статус `confirmed`, `likely` или `hypothesis`.
- Ведёт Яндекс отдельной дорожкой: YandexAdditional, Clean-param, Вебмастер, коммерческие сигналы.
- Для AI-поиска проверяет, может ли страница попасть в ответы ChatGPT, Perplexity, Google AI Overviews и Алисы AI, кого из ботов пускает robots.txt и не режет ли их WAF. llms.txt — как опция, не как обязательный файл.
- Пишет ТЗ и статьи по ТЗ, где у каждой цифры есть источник, обновляет старые страницы, редактирует и убирает признаки нейросети из текста на русском и английском. `factdiff.py` показывает, какие числа, даты и ссылки пропали после правки.
- Читает выгрузки Search Console, Вебмастера и GA4: сравнение периодов, просадки, запросы рядом с топом.
- Бесплатно, лицензия MIT. Платные API не нужны, скрипты написаны на стандартной библиотеке Python. Сайт по умолчанию не обходит: одна страница или до 20 адресов по очереди с паузой.

## Установить одним промптом

Скопируйте промпт целиком и отдайте своему агенту: Claude Code, Codex, Cursor, Copilot, Gemini CLI или другому, у которого есть доступ к файлам. Он определит, где работает, положит папку `papa-seo/` в нужное место, проверит её и отчитается. Ничего не удаляет и не перезаписывает: если папка с таким именем уже есть, остановится и спросит.

```text
Поставь мне скил papa-seo: SEO-аудит, Яндекс, AI-поиск и SEO-тексты, MIT, https://github.com/AffPapa/papa-seo. Иди по шагам, ничего не удаляй и не перезаписывай.

1. Определи, где ты работаешь. По папкам: ~/.claude — Claude Code; ~/.codex или ~/.agents — Codex; ~/.cursor или .cursor в проекте — Cursor; ~/.codeium/windsurf или .windsurf — Windsurf; ~/.copilot или .github/skills — GitHub Copilot; ~/.gemini — Gemini CLI; ~/.openclaw — OpenClaw; ~/.hermes — Hermes. Если ты и так знаешь, кто ты, это важнее папок. Если файловой системы у тебя нет (ChatGPT, claude.ai), остановись и скажи: туда скил ставят иначе, инструкция в README репозитория.

2. Возьми пакет: git clone https://github.com/AffPapa/papa-seo.git во временную папку. Без git — скачай https://github.com/AffPapa/papa-seo/archive/refs/heads/main.zip и распакуй; папка скила внутри архива лежит по пути papa-seo-main/papa-seo/. Нужна только папка papa-seo/ (в ней SKILL.md), остальное из клона не копируй.

3. Куда класть, чтобы получилось <путь>/papa-seo/SKILL.md. Claude Code: ~/.claude/skills/ для всех проектов или <проект>/.claude/skills/ для одного. Codex: ~/.agents/skills/ или <проект>/.agents/skills/. Cursor: <проект>/.agents/skills/ или ~/.cursor/skills/. Windsurf: <проект>/.windsurf/skills/ или ~/.codeium/windsurf/skills/. Copilot: <проект>/.github/skills/ или ~/.copilot/skills/. Gemini CLI: ~/.gemini/skills/ или <проект>/.gemini/skills/. OpenClaw: <workspace>/skills/ или ~/.openclaw/skills/. Hermes: ~/.hermes/skills/. Если на машине есть и ~/.claude, и ~/.agents (или ~/.codex), положи копию в оба: ~/.claude/skills/papa-seo и ~/.agents/skills/papa-seo — Claude Code не читает .agents/skills, а Codex не читает .claude/skills. Если хост не определился, но файлы есть — две копии в проект: <проект>/.agents/skills/papa-seo и <проект>/.claude/skills/papa-seo. Если я не сказал, глобально или в проект: ставь глобально (для всех проектов) и скажи об этом в отчёте; в проект — только если я попросил.

4. Перед копированием проверь, что папки papa-seo в целевом месте ещё нет. Есть — остановись и спроси, ничего не трогай. Сначала создай родительскую папку, если её нет (mkdir -p <путь>), затем копируй папку целиком (cp -R). Чужие файлы не меняй. Временную папку с клоном или архивом после этого можно удалить, только её.

5. Проверь каждое место: test -f <путь>/papa-seo/SKILL.md && python3 <путь>/papa-seo/scripts/page_facts.py --help. Нужен Python 3.10 или новее, сторонних пакетов нет.

6. Срабатывание. Claude Code, Codex, Cursor, Windsurf, Copilot, OpenClaw и Hermes подхватывают скил сами по описанию в SKILL.md; Gemini CLI предлагает его, а активацию подтверждаю я. Если ставишь в проект и в его корне уже есть CLAUDE.md, AGENTS.md или файл правил агента, допиши в конец одну строку, ничего не удаляя (если файл не кончается переводом строки, сначала добавь его): «Для SEO-задач, проверки страниц и SEO-текстов используй скил papa-seo (папка <путь>/papa-seo)». Нового файла ради этой строки не создавай.

7. В конце отчитайся: куда положил (полные пути); как вызвать — Claude Code, Cursor, Copilot и Hermes: /papa-seo, Codex и OpenClaw: $papa-seo, Windsurf: @papa-seo, или просто «проверь страницу https://…»; как удалить — rm -rf <путь>/papa-seo плюс убрать добавленную строку из правил (в Codex можно ещё отключить через [[skills.config]] enabled = false в ~/.codex/config.toml, в Gemini CLI — gemini skills uninstall papa-seo). Если на каком-то шаге что-то не сошлось, скажи, что именно, и следующий шаг не делай.
```

Промпт для агента с доступом к файлам: Claude Code, Codex, Cursor, Copilot, Gemini CLI, Windsurf, OpenClaw, Hermes. Руками проверены Claude Code и Codex (26.10.2026), остальные хосты — по их документации. ChatGPT и claude.ai — ниже, там иначе.

## Попробуйте за минуту

### Одна команда: проверить страницу и получить отчёт

```bash
python3 scripts/audit.py https://affpapa.org/neevents --keys "конференции iGaming; афиша конференций" --out otchet.html
```

Два запроса к сайту: сама страница и `robots.txt`. Дальше всё считается локально. Настоящий вывод, запуск 30.10.2026 (в шапке отчёта время UTC, там ещё 29-е):

```text
papa-seo audit 0.2.1 · 2026-10-29T22:14:59Z UTC
адрес: https://affpapa.org/neevents
страниц: 1 · запросов к сайту: 2
проблем 1 · предупреждений 15 · норма 152 · нет данных 19 · не проверяли 190
реестр: проверено 225 из 415 параметров
чинить первым:
  medium: Выведенный тип ради выдачи — FAQPage: FAQ rich result объявлен 08.05.2026, не показывается с 07.05.2026, документация снята 15.06.2026. Разметка не вредит, но карточек в выдаче не даёт.
  medium: Обязательные и рекомендуемые поля: ItemList / Carousel — ItemList / Carousel: документация Google требует всё, что нужно; из рекомендуемых нет — name
  medium: Ключ в H1 — Ни одной фразы: конференции iGaming; афиша конференций
  medium: Ключ не встречается нигде — Не встречается нигде: афиша конференций
  low: Дубли @id — Повторяются @id: 1
HTML-отчёт: otchet.html
```

Это наша собственная страница, и находки на ней настоящие: FAQPage размечен под rich result, которого Google больше не показывает, а второй ключ на странице не встречается ни разу.

В `otchet.html` — таблицы по тринадцати группам: у каждой строки статус, значение, фрагмент-доказательство и что делать. Открывается без интернета, светлая и тёмная темы, печатается. Машинно то же самое — `--json otchet.json`. До двадцати адресов за раз — `--pages list.txt`.

Чего в отчёте нет: балла «SEO 87 из 100». Такой балл складывается из весов, которых никто не публиковал. Чего отчёт не прячет: 190 параметров он на этой странице не проверял, и у каждого написано почему — «проверки нет», «нужен обход сайта», «нужен браузер или выгрузка». Непроверенное не считается исправным.

### Проверить страницу агентом: совпадает ли разметка с текстом

```text
papa-seo page https://affpapa.org/neevents/piterskie-razborki — сверь даты и время в JSON-LD с тем, что написано на странице.
```

Так скил отработал 24.10.2026 на affpapa.org, сайте авторов пакета. В JSON-LD события стоит `"startDate":"2026-10-25T19:00:00+00:00"`, а на странице написано «начало в 19:00», и речь о Санкт-Петербурге, где UTC+3. Google показал бы начало в 22:00 по Москве и конец в 02:00 следующего дня.

Результат: находка `schema.event_timezone_shift` со статусом `confirmed` и severity medium, обе строки HTML как доказательство, правка (выводить смещение города, +03:00, а не +00:00) и способ проверки: `page_facts.py` по трём событиям из разных городов. Проверено одно событие из ~670 в карте сайта, поэтому вывод «ошибка в шаблоне» скил оставил предположением.

### Проверить robots.txt на AI-ботов и YandexAdditional

```text
посмотри наш robots.txt https://example.ru/robots.txt: кого из AI-ботов пускаем, кого нет, и закрыты ли мы от ответов Алисы
```

Результат: таблица «бот × URL → разрешено или запрещено» по ботам поиска, обучения и загрузки по запросу, находки с пометкой `engine: yandex` и, если попросите, правка robots.txt диффом.

Частая ошибка, которую скил ловит: YandexAdditional не подчиняется ни `User-agent: *`, ни группе `Yandex`, ему нужна своя группа. «Закрыли всех звёздочкой» его не закрывает.

## Режимы

Просить можно обычными словами («проверь страницу», «составь ТЗ», «обнови статью») или назвать режим: `papa-seo audit example.ru`.

| Режим | Что делает |
|---|---|
| `page` | одна страница или HTML-файл до публикации: title, description, заголовки, canonical, разметка, индексируемость |
| `audit` | SEO-аудит сайта по выборке адресов: статусы, редиректы, robots.txt, sitemap, разметка, скорость, внутренние ссылки; итог — отчёт с покрытием «проверено N из ~M» |
| `yandex` | дорожка Яндекса: YandexAdditional, Clean-param, Вебмастер, коммерческие сигналы, переезды |
| `geo` | AI-поиск (GEO): допуск к ответам ChatGPT, Perplexity, AI Overviews и Алисы AI, боты в robots.txt, WAF, llms.txt |
| `plan` | семантика: интенты, кластеры, карта «запрос → страница», каннибализация |
| `brief` | ТЗ копирайтеру: интент, угол, структура, факты с источниками, вопросы эксперту |
| `write` | статья или текст страницы по ТЗ, затем фактчек и де-AI вычитка |
| `refresh` | обновление старой страницы по выгрузке Search Console и текущей выдаче |
| `edit` | редактура и рерайт без потери фактов, удаление признаков ИИ из текста |
| `landing` | лендинг или коммерческая страница без выдуманных отзывов, цифр и гарантий |
| `links` | перелинковка: сироты, глубина, точное предложение для вставки ссылки; внешние ссылки по бесплатным данным |
| `fix` | патч или черновик: robots.txt, JSON-LD, title, шаблон; выкладка только после вашего «да» |
| `measure` | Search Console, Вебмастер, GA4 на чтение: сравнение периодов, просадки, запросы рядом с топом |

Логи сервера, переезды, локальное SEO, интернет-магазины, hreflang, шаблонные страницы, бэклинки и метрики текста подключаются, когда о них спрашивают.

### SEO-аудит сайта

Первые два примера — из того же аудита affpapa.org 24.10.2026: 15 страниц по очереди с паузой, robots.txt и индекс sitemap.

<details>
<summary>Сверить текст обзора с характеристиками той же страницы (кейс affpapa.org)</summary>

```text
papa-seo page https://affpapa.org/nepartners/1win-partners
И английскую пару /en/nepartners/1win-partners. Сверь текст обзора с блоком «Характеристики»: страны, выплаты, всё, что можно проверить по той же странице.
```

Что нашлось 24.10.2026: обзор называет рынками программы Германию, США и Украину, а блок «Характеристики» той же страницы держит эти страны в «Запрещённых ГЕО». В английской паре та же ошибка. Находка `confirmed`, severity high. Правка — в генераторе обзоров: передавать в промпт только целевые ГЕО и не публиковать обзор, если страна из текста стоит в запрещённых.

Проверена одна пара RU/EN из ~1 580 карточек. Сколько обзоров затронуто, по одной странице не видно.

</details>

<details>
<summary>Найти параметрические URL, открытые для обхода (кейс affpapa.org)</summary>

```text
papa-seo audit affpapa.org, без обхода: 15 адресов из urls.txt, один поток, пауза 4 секунды. Сначала robots.txt и sitemap, потом страницы. Отдельно посмотри параметрические URL, на которые ссылаются карточки.
```

Что нашлось: `/neblask/compare?brands=1win,stake` отдаёт `index, follow`, 544 663 байта HTML и canonical на хаб `/neblask/compare` с другим содержимым. Ссылки на такие пары стоят на паспортах брендов, брендов 2 555, а порядок пары даёт отдельный URL. Правила для `/neblask/compare?*` в robots.txt нет.

Статус `likely`, а не `confirmed`: сколько таких адресов уже в индексе и как часто их обходят боты, без Вебмастера и логов не видно. Правок две, на выбор владельца: закрыть комбинации от обхода или оставить белый список пар со своим title и self-canonical.

</details>
<details>
<summary>Аудит сайта по выборке URL без обхода</summary>

```text
papa-seo audit example.ru. Сайт не обходить, сервер слабый. Вот 15 адресов: главная, по две страницы каждого шаблона — urls.txt. Пауза 3 секунды.
```

Результат: отчёт по `templates/report.md`: вердикт, что сделать первым, находки по severity, строка покрытия «проверено N из ~M URL», раздел «Не проверено».

«На всём сайте нет X» скил по выборке не напишет — только «в проверенных N страницах».

</details>

### Семантика и кластеры

<details>

## Скрипты без агента

Те же проверки можно запустить руками. Команды выполняются из папки скила (например, `cd ~/.claude/skills/papa-seo`), результат — JSON.

Почти всегда достаточно первой: `audit.py` сам вызывает остальные и собирает их вывод в один отчёт. Отдельные скрипты нужны, когда результат идёт дальше в свою обработку.

```bash
# всё про страницу одной командой: сводка, HTML-отчёт, машинный JSON
python3 scripts/audit.py https://example.ru/uslugi/ --keys "ремонт квартир; ремонт под ключ" \
  --out otchet.html --json otchet.json

# до 20 адресов по очереди, пауза не меньше 2 секунд, плюс проверки по сайту
python3 scripts/audit.py --pages urls.txt --out otchet.html

# какие параметры умеет считать эта версия и из чего
python3 scripts/audit.py --list-checks

# таблица доступа robots.txt для поисковых и AI-ботов
python3 scripts/robots_check.py https://example.ru/robots.txt --url / --url /catalog/?utm_source=x \
  --bots Googlebot,YandexBot,YandexAdditional,OAI-SearchBot,GPTBot,ClaudeBot --out robots.json

# факты одной страницы; для файла до публикации — ./build/page.html --base-url https://example.ru/uslugi/
python3 scripts/page_facts.py https://example.ru/uslugi/ --out facts.json

# до 20 страниц по очереди, пауза не меньше 2 секунд
python3 scripts/page_facts.py --urls-file urls.txt --delay 3 --out batch.json

# sitemap без обхода перечисленных адресов
python3 scripts/sitemap_check.py https://example.ru/sitemap.xml --site https://example.ru \
  --follow-index --max-children 2 --out sitemap.json

# граф внутренних ссылок: сироты, глубина, PageRank
python3 scripts/link_graph.py edges.csv --pages sitemap_urls.txt --csv-out nodes.csv --out graph.json

# знаки, ключи по основам, тошнота и вода (оценка)
python3 scripts/text_metrics.py article.md --keys "ламинат для кухни; влагостойкий ламинат" --out metrics.json

# что пропало и появилось после правки: числа, даты, деньги, URL, имена
python3 scripts/factdiff.py before.md after.md --out diff.json
```

Ещё три скрипта: `deai_scan.py` ищет штампы, артефакты чат-ботов и невидимые символы, `schema_check.py` разбирает JSON-LD и микроданные отдельно от страницы, `bot_verify.py` проверяет по логу, настоящий ли Googlebot, YandexBot или Bingbot. У `text_metrics.py` есть режим `--compare до после`. Флаги у всех — `--help`.

## Что внутри

```text
papa-seo/
  SKILL.md       роутер: запрос → режим → нужные модули
  policies/      безопасность, правила доказательств, лестница полномочий
  modules/       29 модулей, по файлу на функцию
  references/    реестр 415 параметров, датированные факты со ссылками, мифы, ростер ботов, Яндекс, типы страниц, русский стиль
  templates/     схема находки, ТЗ, отчёт, контекст проекта, профиль голоса
  scripts/       12 скриптов, 11 с командной строкой, Python 3.10+, только стандартная библиотека
  tests/         python3 -m unittest discover -s tests
evals/           сайт-фикстура с заложенными ошибками и ключом ответов
```

Модули по группам:

- аудит: `tech-audit`, `indexing`, `on-page`, `schema`, `performance`, `eeat`, `report`;
- спрос и выдача: `semantics`, `serp`, `measure`;
- Яндекс и AI-поиск: `yandex`, `geo`;
- ссылки: `links`, `backlinks`;
- тексты: `brief`, `write`, `factcheck`, `edit`, `deai`, `voice`, `headlines`, `landing`, `text-metrics`;
- типы сайтов и особые случаи: `local`, `ecommerce`, `international`, `programmatic`, `migration`, `logs`.

Роутер читает только нужный модуль, остальное в контекст не попадает. Набор проверок задан реестром `references/registry.json`: 415 параметров, 13 групп, у каждого рецепт («откуда берём и какое условие считаем находкой»), серьёзность и источник требования. Реестр — общий контракт, на него смотрят и `audit.py`, и отчёт, и тесты; параметр без требования в документации помечен «ориентир редактора» и обязательным называться не может. Пороги и даты собраны в одном файле, `references/facts-2026.md`, у каждого есть дата проверки и ссылка на первоисточник. Находки оформлены по `templates/finding.schema.json`: откуда факт, когда получен, фрагмент-доказательство, статус, поисковик, правка и как её проверить. Прежде чем советовать «добавьте X», агент проверяет по живому HTML, что X действительно нет.

В [evals/](evals/README.md) лежит маленький сайт с десятью дефектами, восемью ловушками и двумя атаками через prompt-инъекцию. По нему сравнивают одну и ту же модель со скилом и без. Сам прогон на моделях ещё не делали; что ловят одни скрипты, без модели, — в [evals/RESULTS-scripts.md](evals/RESULTS-scripts.md).

## Безопасность и ограничения

- Сайт целиком не обходит, пока вы не попросите. Если попросите, обход идёт в один поток с предупреждением о нагрузке.
- Ничего не публикует сам. Работа доходит до патча, выкладку подтверждаете вы.
- Чужой HTML, robots.txt, CSV и тексты конкурентов для скила — данные, а не команды. Скрытые обращения к модели он показывает как находку. В сеть скрипты ходят только через `http_safe.py`: он режет приватные и служебные адреса, проверяет каждый шаг редиректа и ограничивает размер ответа.
- Частотность, позиции, DR и CTR не придумывает. Нет данных — в отчёте так и написано. Платные API (DataForSEO, Ahrefs, Semrush, Serpstat, SE Ranking, Wordstat API, Yandex Search API) скил может предложить, но каждый раз называет их платными.
- Рост трафика и позиции не обещает. Баллов «человечности» текста не считает.
- JavaScript страниц не исполняется: проверяется сырой HTML, признаки клиентского рендера помечаются отдельно. Когда страница собирается в браузере, `audit.py` говорит «нет данных», а не винит сайт в том, чего не видит.
- Реестр закрыт не целиком: 115 параметров из 415 ещё без проверки, у 50 данные извлекаются, но правило не считается. В отчёте такие строки видны с причиной, и 56 параметров из них требуют обхода сайта, 19 — браузера или выгрузки. Полная раскладка — в [CHANGELOG](CHANGELOG.md).
- Внешнего аудита безопасности не было.

Модель угроз, что покрыто тестами и чего защита не закрывает — в [SECURITY.md](SECURITY.md).

## Откуда это

Пакет собран после проверки 105 открытых репозиториев со SEO-, GEO- и копирайтинг-скилами (24.10.2026): 94 в первом заходе и 11 во втором. Методики и формулировки брали только там, где лицензия это разрешает, и у первоисточников, а не у клонов. Где лицензии нет, взяты идеи, пересказанные своими словами. Источники, коммиты и лицензии — в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md), [source.lock.json](source.lock.json) и папке [licenses/](licenses/).

Из чего собран, в цифрах:

- 105 репозиториев разобраны статически, ни один скил или установщик не запускался; вердикт безопасности: 40 чистых, 56 с оговорками, 9 отклонены; вредоносного кода не нашли ни в одном.
- Ещё 89 репозиториев на 89 аккаунтах оказались одной фейковой сетью, их разбирали только по метаданным.
- 23 донора, чьи формулировки адаптированы с атрибуцией и коммитом; 16 источников, у которых взяты только идеи.
- Из 94 исходных репозиториев у 71 лицензия в порядке, у 10 «MIT» стоит только в README, у 9 лицензии нет или она закрытая, 4 под AGPL, CC BY-SA или с поддельной.
- 17 реализаций де-AI редактуры, почти все восходят к одной странице Wikipedia; Яндекс закрыт у одного донора, YandexAdditional не упомянут ни в одном из 105.
- Не взяли группами: платные API и облачные MCP, реклама внутри отчётов, обход капчи, деинсталляторы по маске, удалённый SKILL.md, авто-merge, куки браузера.

Полная раскладка — кто, что, под какой лицензией, что отбросили и почему, какие «нормы» из чужих скилов не прошли проверку по первоисточникам — в [docs/RESEARCH.md](docs/RESEARCH.md).
