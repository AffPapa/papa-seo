# Конструкторы и CMS: что подтверждено справкой

Справочник для `modules/newsite.md` и чек-листа `references/launch-checklist.md`. Здесь только то, что написано в официальной справке конструктора; у каждого факта ссылка и дата проверки. Чего в справке не нашли — «проверить в справке конструктора», а не догадка. Названия пунктов меню меняются: перед советом пользователю сверить с его интерфейсом.

Пометка: ✅ — страница справки открыта 17.11.2026, факт прочитан на ней; ❓ — в открытых страницах не нашли, проверить в справке конструктора.

## Tilda

Источники:
- [T1] help-ru.tilda.cc/search-engine — справка «Поисковая оптимизация» (дата обновления на странице не указана), проверено 17.11.2026;
- [T2] tilda.cc/ru/answers/a/robots-edit/ — ответ «Можно ли отредактировать robots.txt», проверено 17.11.2026.

| Вопрос | Что в справке | Статус |
|---|---|---|
| robots.txt | создаётся автоматически; править вручную — «Настройки сайта» → «SEO» → «Редактирование robots.txt», режим «Ручное управление», лимит 60 КБ [T1, T2] | ✅ |
| Цена ручного режима robots.txt | изменения настроек индексации сайта и страниц перестают попадать в файл сами, их вносят руками; ссылки на служебные карты (`sitemap-store.xml`, `sitemap-feeds.xml`) тоже убирают вручную [T1] | ✅ |
| sitemap.xml | собирается по страницам сайта; три режима: автоматический, автоматический с дополнением (свои ссылки в «Дополнительное содержимое к sitemap.xml»), ручной; лимит 3 МБ или 3 000 записей; там же, «Настройки сайта» → «SEO» [T1] | ✅ |
| Карта и смена домена или HTTPS/WWW | адреса, добавленные в дополнение к sitemap.xml, сами не обновляются — поправить вручную [T1] | ✅ |
| Запрет индексации страницы | «Настройки страницы» → «SEO» → «Отображение в поисковой выдаче», галочка «Запретить поисковикам индексировать страницу» [T1]. Каким способом запрет реализован (метатег или robots.txt), справка не говорит — проверить в исходном коде опубликованной страницы и в robots.txt | ✅ / ❓ |
| Запрет индексации сайта целиком | «Настройки сайта» → «SEO», галочка «Запретить поисковикам индексировать сайт»; справка советует для надёжности поставить пароль [T1] | ✅ |
| Главный адрес | у подключённого домена он канонический, служебный адрес на tilda.ws поисковики игнорируют [T1] | ✅ |
| HTTPS и www | «Настройки сайта» → «SEO» → «Редиректы для www и https»: редирект с HTTP на HTTPS и переключатель редиректа на www; там же — HTTPS в robots.txt, sitemap.xml и canonical [T1] | ✅ |
| 301 со старых адресов | «Настройки сайта» → «SEO» → «Редиректы страниц (Code 301)»: в пределах одного домена и только для адресов, которых на сайте нет [T1] | ✅ |
| canonical | для подключённого домена ставится сам; вручную — «Настройки страницы» → «SEO» → «Отображение в поисковой выдаче» → «Задать специальные мета-данные» → «Каноническая ссылка на страницу» [T1] | ✅ |
| Вебмастер и Search Console | «Настройки сайта» → «SEO» → сервис → «Подключить»; условие — опубликована главная [T1]. Какой способ подтверждения прав использует Tilda, на странице не сказано | ✅ / ❓ |
| Адрес страницы | задаётся «читаемый адрес» вида `/about` [T1]. Можно ли вложенный путь `/uslugi/implantaciya` — в открытых страницах не сказано | ❓ |
| Свой код в `<head>` (метатег подтверждения, JSON-LD) | в открытых страницах нет | ❓ |
| Свой файл в корне (`llms.txt`, файл подтверждения прав) | в открытых страницах нет; упомянуты только robots.txt и sitemap.xml | ❓ |

## Wix

Источники:
- [W1] support.wix.com/en/article/editing-your-sites-robotstxt-file (обновлена 16.11.2026), проверено 17.11.2026;
- [W2] support.wix.com/en/article/embedding-custom-code-on-your-site (обновлена 09.04.2026), проверено 17.11.2026.

| Вопрос | Что в справке | Статус |
|---|---|---|
| robots.txt | редактор: панель сайта → SEO & GEO → Tools and settings → Robots.txt Editor; откат — Reset to Default [W1] | ✅ |
| robots.txt по умолчанию | разрешает ботам все страницы и содержит адрес sitemap [W1] | ✅ |
| Поддержка | правки robots.txt — «advanced feature», поддержка Wix с ними не помогает [W1] | ✅ |
| Запрет индексации страницы | через настройки SEO страницы; метатег robots назван как другой способ [W1] | ✅ |
| Свой код в `<head>` | Settings → Development & integrations → Custom Code → Add Custom Code; место: Head, Body – start, Body – end; на все страницы или выбранные [W2] | ✅ |
| Условие для своего кода | сайт опубликован и к нему подключён домен [W2] | ✅ |
| Коды подтверждения прав | справка велит ставить коды отслеживания и подтверждения в Head [W2] | ✅ |
| Аналитика | Google Analytics и Tag Manager через Custom Code не работают, для них — маркетинговые интеграции [W2] | ✅ |
| sitemap.xml | [W1] только ссылается на отдельную статью; как карта собирается — проверить там | ❓ |
| Вложенные адреса страниц, файлы в корне, редиректы 301 | в открытых страницах нет | ❓ |

## WordPress (своя установка, WordPress.org)

Это справка самостоятельной установки WordPress. У WordPress.com свои настройки и тарифные ограничения — по нему здесь ничего не проверено.

Источники:
- [P1] wordpress.org/documentation/article/settings-reading-screen/ (обновлена 08.06.2024), проверено 17.11.2026;
- [P2] wordpress.org/documentation/article/settings-permalinks-screen/ (обновлена 08.06.2024), проверено 17.11.2026.

| Вопрос | Что в справке | Статус |
|---|---|---|
| Закрыть сайт на время разработки | Settings → Reading → «Discourage search engines from indexing this site» [P1] | ✅ |
| Что делает эта галочка | с версии 5.3 выводит в `<head>` `<meta name='robots' content='noindex,nofollow' />` (если тема вызывает `wp_head`); до 5.2 отдавала в robots.txt `Disallow: /`; доступ не закрывает — «it is up to search engines to honor your request» [P1] | ✅ |
| Главная | Settings → Reading: показывать последние записи или выбранную статическую страницу; страница записей отдельно [P1] | ✅ |
| Структура адресов | Settings → Permalinks: Plain (`/?p=123`), Day and name, Month and name, Numeric, Post name (`/sample-post`), своя схема из тегов; свои префиксы рубрик и меток [P2] | ✅ |
| Сервер для ЧПУ | если `.htaccess` недоступен для записи, WordPress показывает правила mod_rewrite, их вносят вручную [P2] | ✅ |
| Вложенный адрес страницы через родителя | в открытых страницах нет | ❓ |
| Встроенная карта сайта, robots.txt, свой код в `<head>` | в открытых страницах нет; часто это делает тема или плагин — смотреть их документацию | ❓ |

## Как дополнять

Открыть страницу справки конструктора (одна-две за раз, без обхода), записать факт с источником и датой проверки. Сторонние статьи, форумы и ответы поисковых ассистентов источником не считаются: 17.11.2026 сводка веб-поиска утверждала, что robots.txt в Tilda не редактируется, а справка Tilda [T2] говорит обратное.
