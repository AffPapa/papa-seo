# Яндекс: справочник

Пересказ справки Яндекс Вебмастера, проверено 24.10.2026 (ревизия документации r21762422). Справка Яндекса под обычным авторским правом: здесь только пересказ и ссылки. База ссылок: `https://yandex.ru/support/webmaster/ru/` (дальше — `…/`). Боты и их поведение — `ai-bots.yaml`. Факты Google — `facts-2026.md`.

Статусы: ✅ — открыто в первоисточнике 24.10.2026; ◐ — взято из исследования пакета, первоисточник в этот заход не открывался; ❓ — не подтверждено.

## 1. robots.txt по правилам Яндекса

| Правило | Статус | Источник |
|---|---|---|
| Файл `robots.txt` в корне, TXT, до 500 КБ; сервер должен ответить 200 OK (при редиректе — конечный файл). Файл, не отвечающий требованиям, считается разрешающим всё | ✅ | …/controlling-robot/robots-txt |
| Кириллица в файле и заголовках запрещена: домены в Punycode, пути в процентной кодировке. Названия директив без учёта регистра, значения (пути, имена роботов) — с учётом | ✅ | там же |
| Выбор группы: роботы Яндекса читают группы `Yandex` и `*`. Если есть группа `Yandex`, группа `*` для роботов Яндекса не используется. Если есть группа конкретного робота (`YandexBot`), не используются ни `Yandex`, ни `*` | ✅ | …/robot-workings/user-agent |
| Часть роботов Яндекса игнорирует даже группу `Yandex`; для них правило пишут с их собственным именем | ✅ | там же; список — …/robot-workings/check-yandex-robots |
| `Allow`/`Disallow` сортируются по длине префикса, побеждает самое длинное совпадение; при равной длине — `Allow`. Порядок строк не важен | ✅ | …/robot-workings/allow-disallow |
| `*` — любая последовательность, в конце правила неявно стоит `*`; `$` его отменяет. Пустой `Disallow:` = разрешить всё; пустой `Allow:` не учитывается | ✅ | там же |
| `Clean-param: p1&p2 [путь]` — параметры, которые не влияют на содержимое (метки, сессии, реферальные коды). Путь — префикс из символов `A-Za-z0-9.-/*_`, в конце неявная `*`; без пути — весь сайт. До 500 символов на правило, с учётом регистра, директив может быть несколько, межсекционная (работает в любом месте файла). `Disallow` важнее: закрытая страница не индексируется, даже если подпадает под `Clean-param` | ✅ | …/robot-workings/clean-param |
| `Crawl-delay` не учитывается с 22.02.2018. Скорость задаётся в Вебмастере: Индексирование → Скорость обхода | ✅ | …/robot-workings/crawl-delay, …/service/crawl-rate |
| `Host` не учитывается (с 2018), главный адрес задаётся 301-редиректом и разделом «Главный и неглавные адреса сайта» | ◐ | research/03 §4; …/yandex-indexing/site-addresses |
| Закрытая в robots.txt страница может остаться в поиске. Чтобы убрать — `noindex`, и страницу не закрывать, иначе робот не увидит директиву | ✅ | …/controlling-robot/robots-txt |
| Коды ответа 4xx/5xx на сам robots.txt — в справке не описаны отдельно, применяем RFC 9309 (facts-2026 §1) | ❓ | — |

Типовые ошибки под Яндекс: группа `User-agent: Yandex` скопирована без части правил из `*` (правила `*` для Яндекса уже не действуют); `Host` и `Crawl-delay` оставлены как рабочие; UTM и сессии плодят дубли без `Clean-param`; `YandexAdditional` закрыт через `*` и «не работает».

## 2. Роботы Яндекса

Колонка в справке называется «учитывает общие правила robots.txt»: «нет» значит, что правила для `*` (а иногда и для `Yandex`) роботу не адресованы.

| Робот | Назначение | Общие правила |
|---|---|---|
| YandexBot | основной индексирующий | да |
| YandexImages, YandexVideo, YandexMedia | картинки, видео, мультимедиа | да |
| YandexAdditional, YandexAdditionalBot | токены для ограничения показа в быстрых ответах с YandexGPT и в ответах Алисы AI; запросов не делают | **нет** |
| YandexRenderResourcesBot | ресурсы для рендеринга JS; игнорирует robots.txt, если HTML-страница доступна роботу | нет |
| YandexFavicons, YandexMobileBot, YandexMetrika, YandexDirect, YaDirectFetcher, YandexDialogs и др. | служебные | нет |
| YandexPagechecker | валидатор микроразметки | да |
| YandexSpravBot | Яндекс Бизнес | да |
| YandexAccessibilityBot | проверка доступности, до 3 запросов в секунду, настройку скорости игнорирует | нет |

Подлинность (…/robot-workings/check-yandex-robots, ✅): обратный DNS по IP из лога → имя должно кончаться на `yandex.ru`, `yandex.net` или `yandex.com` → прямой DNS по этому имени → тот же IP. Списка IP Яндекс не публикует (сети AS13238, AS208722, AS212066, адреса меняются). Есть инструмент Вебмастера «Проверка IP-адреса». Скрипт: `python3 scripts/bot_verify.py`. Версию браузера в строке User-Agent не проверять — она меняется.

## 3. Метатеги и X-Robots-Tag

✅ …/controlling-robot/metatags

- Поддерживаются `noindex`, `nofollow`, `none` (= noindex, nofollow), `noarchive`; разрешающие `index`, `follow`, `archive`, `all` нужны, только чтобы отменить запрет.
- То же — в заголовке `X-Robots-Tag`, несколько заголовков в одном ответе допустимы.
- Только для Яндекса — `<meta name="yandex" content="…">`; общие и яндексовые директивы складываются.
- Если страница закрыта в robots.txt, метатеги и заголовки не действуют.
- Аналогов `nosnippet`, `max-snippet`, `data-nosnippet` в справке нет. Запретить показ контента в ответах Алисы AI можно только через `YandexAdditional`/`YandexAdditionalBot` в robots.txt (§5).
- Ещё учитываются `description` (может пойти в сниппет), `viewport`, `refresh` (временный редирект; используется при переезде). Про `keywords` справка пишет, что он «может влиять» на соответствие запросам — набивать его не надо, это не повод что-то добавлять.
- Особые: `disallow-extended-services-display`, `disallow-extended-realty-display` — скрыть страницу из тем Услуги и Квартиры, не из Поиска.

## 5. Алиса AI и быстрые ответы

✅ …/alice, …/service/alice-answers, …/adding-site/indexing-prohibition, …/epos

- Ответы Алисы AI показываются в поисковой выдаче, в объектных ответах и на отдельной вкладке; дополняют выдачу, а не заменяют её. До Алисы AI (2025) были быстрые ответы на YandexGPT (2023).
- Как строится ответ: Алиса уточняет запрос и разбивает его на подвопросы, ходит с ними в Поиск, собирает ответ из смысловых блоков. Опирается на источники, которые высоко ранжируются. Ссылки в ответе не ранжированы, их может быть больше, чем на странице выдачи, одна страница может повторяться. Ответ на один запрос меняется от дня ко дню.
- Отбор источников — по аспектам ЭПОС (§6).
- **Запрет показа:** своя группа `User-agent: YandexAdditionalBot` (или `YandexAdditional`) с `Disallow`. Учитывается за 2–14 дней. Правило `*` и `Yandex` на эти токены не действует.
- **Мониторинг (бесплатно, вручную):** Вебмастер → «Видимость сайта в Алисе AI» (`webmaster.yandex.ru/site/efficiency/alice/`). Показывает долю ответов Алисы AI с упоминанием сайта среди запросов, где сайт уже есть в выдаче (Share of Voice), динамику, примеры запросов с сайтом и без, сайты, которые упоминаются рядом. Данные за 3 месяца, обновление раз в неделю; кликов и показов там нет. Управлять попаданием в ответы инструмент не позволяет.
- Публичного API для этого раздела нет (по данным artwist-polyakov/polyakov-claude-skills, проверено автором 03.09.2026). Скрейпинг страницы с cookie сессии пакет не использует.

## 6. ЭПОС — аспекты качества Яндекса

✅ …/epos. Яндекс сам описывает четыре группы аспектов, общих для ранжирования и для отбора источников Алисы AI:

| Аспект | Вопрос для самопроверки (пересказ) | Что смотреть на странице |
|---|---|---|
| Экспертность | доверял бы я этому автору и бизнесу на месте пользователя? | кто автор и в чём его опыт; реальный адрес, реквизиты, контакты компании; специализация, сертификаты, портфолио, отзывы |
| Полезность | помогла ли страница решить задачу? | работает ли нужный сценарий, сколько усилий до результата, удобство на всех устройствах, цели в Метрике |
| Оригинальность | есть ли ценность, которую трудно найти в другом месте? | собственные данные и опыт; уникальность текста сама по себе ценностью не считается, переписанное или сгенерированное без добавленной ценности — нет |
| Содержательность | дан ли конкретный, полный и короткий ответ? | плотность смысла, реальные плюсы и минусы, без воды и формальных сравнений |

Плюс релевантность — соответствие задаче пользователя, а не словам запроса (товар не в наличии или без доставки в регион проигрывает).

## 7. Коммерческие и юридические сигналы (чек-лист без баллов)

Опора — раздел «Экспертность» ЭПОС и разделы справки о карточке юрлица/ИП, контактах, статусе «Надёжный бизнес», отзывах. Весов у Яндекса нет — не выдумывать. Проверять видимые на сайте элементы:

- юрлицо или ИП, ИНН/ОГРН, юридический и фактический адрес, телефон, почта, часы работы;
- страницы оферты, политики обработки персональных данных, cookies; условия оплаты, доставки, возврата, гарантии;
- цены или порядок расчёта цены, наличие, регион обслуживания;
- автор и его опыт на экспертных страницах; дата обновления там, где важна свежесть.

Отсутствие элемента — находка, только если для этого типа страницы он ожидаем (у статьи глоссария не бывает доставки). «Поведенческие факторы» по TTFB или размеру HTML не оценивать — это технические эвристики, не поведение пользователей.

## 9. IndexNow

✅ …/indexing-options/index-now, …/indexnow/key, …/indexnow/reference

- Эндпоинт `https://yandex.com/indexnow`: один URL — GET с `url`, `key`, опц. `keyLocation`; много — POST JSON с `host`, `key`, `urlList` (до 10 000 URL).
- Ключ: 8–128 символов `a-zA-Z0-9-`, UTF-8, текстовый файл без HTML. В корне сайта имя файла = ключ; в подкаталоге — указывать `keyLocation`, ключ действует только для URL этого каталога. Для поддоменов — свой ключ.
- Ответы: 200 — принято; 202 — ключ ещё проверяется; 400 — неверный запрос; 403 — ключ не загрузился или не подходит; 405 — метод; 422 — неверный URL, ключ или `keyLocation`; 429 — слишком много запросов с IP.
- Отправлять только новые, изменённые и удалённые страницы. Индексацию не гарантирует. Для маленького сайта Яндекс советует Переобход страниц в Вебмастере. Поддерживается с 18.10.2021 (◐ research/03).

## 10. Переезд и зеркала

✅ …/yandex-indexing/moving-site

1. Добавить старый и новый адреса в Вебмастер, подтвердить права.
2. Проверить: содержимое совпадает, оба доступны роботу, новый адрес не склеен с чужим сайтом.
3. Редирект 301 (или 302) со старых URL на соответствующие новые; вариант — метатег `refresh`.
4. Вебмастер старого сайта → Индексирование → Переезд сайта → новый адрес.

Частые причины отказа: на целевом сайте `rel="canonical"` указывает на старый адрес; сайт недоступен или медленный; содержимое не совпадает; переезд в другую доменную зону без редиректа; индексирование закрыто в robots.txt; нарушения правил Поиска; заявка отправлена не с того сайта. Отдельно описаны www ↔ без www, HTTP → HTTPS.

## 12. llms.txt и Яндекс

Справка Вебмастера сама публикует `llms.txt` как индекс своей документации. Сведений о том, что роботы Яндекса читают `llms.txt` чужих сайтов или учитывают его в Поиске и Алисе AI, в справке не найдено (24.10.2026). Не советовать его как фактор Яндекса.

## Как обновлять

Открыть страницу справки (у каждой есть `.md`-версия и общий индекс `…/llms.txt`), сверить, поменять статус и дату. Цены перепроверять перед каждым упоминанием в отчёте.
