# Метрики текста (RU/EN)

Считает метрики текста скриптом `scripts/text_metrics.py` и объясняет, что они значат. Всё, кроме простых счётчиков, — **оценка**: формулы рунет-сервисов (Advego, Text.ru и др.) не опубликованы, наши цифры с ними не совпадут. Метрики — отчёт для редактора и заказчика, а не гейт: хороший текст не переписывают ради цифры, плотность ключа и «тошнота» не факторы ранжирования (`references/folklore.md`, facts-2026 §9).

**Когда грузить:** «посчитай знаки без пробелов», «проверь тошноту / воду», «сколько вхождений ключа», «заказчик требует тошноту не выше X», «сравни две версии текста»; как отчёт в конце `write.md` и `edit.md`, если метрики нужны заказчику; при извлечении голоса (`voice.md`).

**Входы:** текст (Markdown, TXT или HTML); ключевые фразы, если нужно считать вхождения; требования заказчика (объём, пороги), если есть; вторая версия текста для сравнения.

## Шаги

1. **Запуск.**
   `python3 scripts/text_metrics.py text.md --keys "купить диван; угловой диван" --out metrics.json`
   HTML: расширение `.html` или флаг `--html` (скрипты, стили и комментарии не считаются). Текст без файла — `-` и stdin. Язык определяется сам, `--lang ru|en` — принудительно.
   Страница целиком: `python3 scripts/text_metrics.py page.html --url https://site.ru/razdel --keys "ключ"` — тогда считаются вхождения **по зонам** (title, description, H1, H2–H6, первый абзац, alt, анкоры, URL). Без `--url` адрес берётся из `canonical` или `og:url`.
   Две версии: `python3 scripts/text_metrics.py --compare before.html after.html --keys "ключ"` — что изменилось, одним и тем же счётом.
2. **Что скрипт не считает текстом:** блоки кода, инлайн-код, HTML-комментарии, URL (счётчики — в `masked`). Заголовки, пункты списков и ячейки таблиц входят в слова и знаки, но не в ритм.
3. **Прочитать отчёт** по таблице ниже. Требования заказчика сравнить с цифрами и записать «соответствует / не соответствует, по оценке этого скрипта».
4. **Сравнение версий.** Запустить на обеих версиях и сравнивать только между собой: один и тот же скрипт, одни и те же ключи.
5. **Если цифра «плохая».** Сначала прочитать текст. Высокая тошнота от названия товара в карточке товара — норма; от повтора одного прилагательного — повод заменить повторы местоимением или перестроить фразу. Высокая вода — повод проверить пустые зачины и подводки (`deai.md`), а не удалять предлоги. Ключ встречается редко, но текст отвечает на запрос — не добавлять вхождения ради числа.
6. **Отдать** короткую сводку: объём в словах и знаках без пробелов, ритм, ключи (точные и морфологические вхождения, зоны без ключа и зоны без данных), оценки тошноты, воды и читаемости с пометкой «оценка», требования заказчика и соответствие им.

## Что считается

| Метрика | Как считает скрипт | Статус | Что значит |
|---|---|---|---|
| Слова | токены с буквами; числа отдельно | точно | объём |
| Знаки с пробелами / без пробелов (збп) | по тексту без разметки Markdown, кода и комментариев | точно (может отличаться от сервисов на разметке) | объём для ТЗ рунета |
| Предложения, абзацы | только сплошной текст; сокращения «т. е.», «г.», «руб.» не рвут предложение | эвристика | основа для ритма |
| Длина предложений: среднее, медиана, разброс (CV) | слова в предложении | точно по разбиению | низкий разброс — текст ровный; порога нет |
| Серии предложений одной длины | ≥ 3 соседних, длины в пределах 20 %, от 5 слов | эвристика, условность чтения | места для перестановки, не ошибка сами по себе |
| Частые основы | простой стеммер RU (упрощённый Snowball) и EN; без служебных слов | оценка | какие слова повторяются |
| Тошнота «классическая» | √ частоты самой частой значимой основы | оценка | рост — признак повторов |
| Тошнота «академическая» | доля самой частой значимой основы среди всех слов, % | оценка | то же, в процентах |
| Вода | доля служебных слов (предлоги, союзы, частицы, местоимения, вводные) | оценка; у сервисов другая формула | сравнивать только версии одного текста |
| Ключ: точное совпадение (`exact_forms`) | те же словоформы в том же порядке; знаки между словами не учитываются | точно по разбиению | «купить диван» ≠ «купили диваны» |
| Ключ: морфологическое (`morphological`) | последовательность основ ключа подряд, без служебных слов, внутри одного предложения | оценка (стеммер без словаря) | «купить диван» находит «купили диваны» |
| Ключ: в любом порядке | все основы ключа в окне длиной ключа + 2 слова | оценка | «угловой диван» находит «диван угловой» |
| Плотность ключа | слова прямых вхождений / все слова, % — и по тексту, и по каждой зоне | оценка | не фактор ранжирования |
| Ключ по зонам | title, description, H1, H2–H6, первый абзац, alt, анкоры, URL, весь текст; внутри зоны вхождение не склеивается через границу элемента | точно по разбору HTML | видно, где ключа нет вообще |
| Ключ в URL | слова URL (дефис, точка, слеш — разделители), процентные коды раскрываются; для кириллицы ещё и транслитерация основ | эвристика для слагов | «uglovye-divany» = основы «углов», «диван» |
| Совстречаемость | какие основы стоят в тех же предложениях, что и ключ | точно по подсчёту | подтемы, которые уже раскрыты; **не «LSI-ключи»** |
| Повторы фраз | n-граммы 2–5 слов, встретившиеся ≥ 2 раз, внутри предложения | точно по подсчёту | буквальные самоповторы |
| Самоповтор, % | слова в повторяющихся n-граммах 3–5 / все слова, % | точно по формуле | что из этого лишнее — решает редактор |
| Канцелярит | счёт по короткому своему списку маркеров + доля отглагольных существительных | оценка | в договоре и науке — норма жанра |
| Пассив | RU: «быть» + краткое причастие и глаголы на -ся (вместе с возвратными); EN: be/get + причастие | эвристика | без разбора подлежащего точнее не выйдет |
| Читаемость EN | Flesch Reading Ease `206.835 − 1.015 × ASL − 84.6 × ASW` и Flesch–Kincaid Grade `0.39 × ASL + 11.8 × ASW − 15.59` | факт по формуле (слоги — эвристика) | шкала автора формулы, не требование поиска |
| Читаемость RU | `206,835 − 1,3 × ASL − 60,1 × ASW` — адаптация Флеша под русские слоги (Оборнева, 2006); слог = гласная | **оценка** | шкалы под веб-тексты нет: сравнивать только версии одного текста |
| Сравнение версий | `--compare до после`: разница по всем метрикам и по ключам в каждой зоне | как исходные метрики | знак разницы ≠ «лучше/хуже» |
| Длинные предложения | доля предложений длиннее границы; граница печатается рядом (по умолчанию 30 слов) | факт по своей границе | ориентир редактора, не норма поиска |

Блок `page_text` — сравнение зон между собой (для HTML; в Markdown часть полей `null`):

| Проверка | Как считает | Статус |
|---|---|---|
| Набивка в title | одна основа больше двух раз + доля заглавных | факт подсчёта; опора — спам-политика keyword stuffing, числа в ней нет |
| title против H1 | пересечение значимых основ, в обе стороны | оценка; порога нет, 0 % бывает законным |
| description = title | нормализованные строки совпадают или одна в другой | факт |
| description — обрезанный первый абзац | нормализованное описание — начало первого абзаца | факт |
| Набивка в заголовках | основа больше чем в половине заголовков своего уровня | факт подсчёта |
| Длина заголовков H2–H6 | распределение, без порога | факт |
| Язык title против текста | только по алфавиту (кириллица/латиница) + значение `<html lang>` | оценка; на коротком title ненадёжно |
| Цифры без источника | предложения с цифрами, рядом слово-указание на источник или год | оценка; ссылку рядом видит `page_facts.py`, не этот скрипт |
| Ответ в начале | слова и предложения первого абзаца, вопрос ли первое предложение | оценка; нормы длины пассажа нет |

Не считаем и не советуем: «LSI-слова» как список для вставки, «уникальность в процентах», балл «человечности» или вероятность ИИ, читаемость для языков кроме RU/EN (формулы нет — поле `unavailable`). Ни Google, ни Яндекс не публиковали шкалу читаемости как фактор ранжирования, поэтому читаемость — метрика редактора, а не цель.

## Правила

| Правило | Почему | Как проверить |
|---|---|---|
| Оценка, не гейт | формулы сервисов закрыты, цифры не совпадут | в отчёте рядом с цифрой «оценка» |
| Ради цифры текст не портят | плотность и тошнота не факторы ранжирования | правки по метрикам объяснены пользой для читателя |
| Сравнивать одним инструментом | разные сервисы считают по-разному | обе версии прогнаны одним скриптом |
| Требование заказчика — записать как его требование | заказчик вправе требовать, но это не закон поиска | в отчёте «требование заказчика: …» |
| Стеммер грубый | без словаря возможны склейки и разрывы основ | при сомнении смотреть `forms` в `stems_top` |
| Ритм — только по сплошному тексту | у списков и таблиц ритма нет | для списков ритм `none` |
| Пустая зона — «нет данных», а не «ключа нет» | в Markdown нет title, description и URL | смотреть `zones_meta.absent` и `words: 0` в зоне |
| «Первый абзац» — по правилу скрипта | берётся первый `<p>` от трёх слов, сначала внутри `<main>`/`<article>` | `zones_meta.first_paragraph_source` |
| Транслитерация URL — эвристика | вариантов записи (х/kh, ц/c/ts) несколько | `translit_stems` отдельно от счётчиков вхождений |

## Чего не делать

- Не ставить пороги («тошнота не выше 4», «вода до 15 %») от себя: только если их назвал заказчик.
- Не добивать ключ до плотности, не разбавлять текст ради «воды», не удалять предлоги ради цифры.
- Не выдавать оценку за показатель Advego или Text.ru.
- Не использовать метрики как доказательство машинного или человеческого авторства.
- Не советовать «вписать ключ в title / H1 / alt» только потому, что в зоне ноль: сначала прочитать, о чём страница и о чём ключ. Ноль в зоне — повод посмотреть, а не правило.
- Не вставлять слова из списка совстречаемости в текст: это статистика соседства, а не список «LSI-ключей».
- Не называть читаемость фактором ранжирования и не подгонять текст под число шкалы.

## Контракт с `audit.py`

`PARAM_MAP` в `scripts/text_metrics.py` связывает id параметров реестра (`registry.json` 0.2.0) с путями в JSON-отчёте: 41 параметр групп `content`, `meta`, `intl`, `ai`. Тест `TestRegistryContract` проверяет, что каждый путь в отчёте есть. Кросс-страничные параметры (дубли title и description по сайту, повтор абзацев между URL) здесь не считаются: нужен набор страниц, их собирает `audit.py`.

## Выход

- Короткая сводка (слова, збп, CV, серии, ключи, тошнота и вода с пометкой «оценка»).
- Полный JSON по `--out`.
- Сравнение с требованиями заказчика, если они есть.
- Строка «Дальше:».
