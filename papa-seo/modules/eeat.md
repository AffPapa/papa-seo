# E-E-A-T, ЭПОС и сущности

Оценивает, видно ли на странице и сайте, кто сделал материал, на каком опыте, зачем и можно ли этому доверять; проверяет, однозначно ли поисковик и AI-системы узнают организацию, авторов и продукты как сущности. Для Google — самооценка people-first и E-E-A-T, для Яндекса — аспекты ЭПОС (`references/yandex.md` §6). Это суждение по признакам, не счётчик: баллов «E-E-A-T 87/100» не ставим без опубликованных весов (policies/evidence.md §5).

**Когда грузить:** «E-E-A-T», «экспертность», «доверие», «авторы», «YMYL», «сущность», «Knowledge Graph», «sameAs», «Wikidata», «о компании», «ЭПОС»; в `audit` — для статей, обзоров, рейтингов, финансовых, медицинских, юридических страниц.

**Входы:** URL или HTML; страницы «О компании», «Контакты», автора; список официальных профилей бренда и авторов (от владельца, не из поиска); сведения о процессе создания контента (кто пишет, кто проверяет, используется ли AI) — от владельца.

## Шаги

1. **Тип страницы и цена ошибки.** YMYL — здоровье, деньги, право, безопасность и другие темы, где ошибка дорого стоит читателю. Для YMYL требования к автору, источникам и прозрачности строже; для глоссария или новости — проще. Тип страницы — `references/page-types.md`.
2. **Кто (Who).** Есть ли подпись там, где читатель её ждёт; ведёт ли она на страницу автора; на странице автора — реальный опыт, специализация, ссылки на подтверждения. Нет данных об авторе — `[NEED: автор, его опыт]`, а не сочинённая биография.
3. **Как (How).** Видно ли, на чём основан материал: собственные замеры, тесты, данные, опыт, методика рейтинга или обзора. Если текст сделан с помощью AI или автоматически — объяснено ли это там, где читатель спросил бы. Сравнения и рейтинги без методики — находка.
4. **Зачем (Why).** Страница сделана, чтобы помочь читателю, или чтобы собрать трафик. Признаки второго — ниже в таблице «тревожные признаки».
5. **Доверие сайта.** Контакты, реквизиты, адрес, правила, политика данных; для коммерческих страниц — чек-лист `references/yandex.md` §7 (он годится и для Google). Источники у цифр и утверждений; дата публикации и обновления — честные: дату не двигать без содержательной правки.
6. **ЭПОС для Яндекса** — пройти четыре вопроса самопроверки (yandex.md §6) и отметить по каждому, что на странице это подтверждает или опровергает.
7. **Сущности.**
   - Organization: один стабильный `@id` (например, `https://site/#organization`) на всех страницах, `name`, `url`, `logo`, `sameAs` только на реальные официальные профили, подтверждённые владельцем.
   - Person для авторов: `@id` на странице автора, `name`, `url`, `sameAs`, связь с Organization; в Article — `author` ссылкой на этот `@id`.
   - Название, описание, логотип одинаковые на сайте, в профилях, справочниках, Яндекс Бизнесе и Google Business Profile.
   - Wikidata/Wikipedia — только если сущность значима по их правилам и есть независимые источники; не создавать записи ради SEO.
   Генерация и проверка JSON-LD — `schema.md`.
8. **Гейт доказательств.** Перед «добавьте автора / Organization / sameAs» — проверить `python3 scripts/page_facts.py <url>`: нет ли уже подписи, JSON-LD, ссылки на автора. Наличие на 3 проверенных страницах не значит «на всём сайте» — писать покрытие.
9. Находки — `policies/evidence.md` (`source_type: live_html` или `user_file`); статус `hypothesis`, если вывод держится на суждении без видимого доказательства.

## Самооценка people-first (по документации Google о полезном контенте)

| Вопрос | Ответ «да» — хорошо |
|---|---|
| Есть ли собственная информация, исследование, анализ, а не пересказ чужого? | да |
| Полно ли раскрыта тема для задачи читателя, есть ли выводы сверх очевидного? | да |
| Заголовок описывает содержание без преувеличения? | да |
| Видно ли, кто и на каком опыте это написал; ясны ли источники? | да |
| Нет ли легко проверяемых фактических ошибок? | да |
| Уйдёт ли читатель, решив задачу, без нового поиска? | да |

**Тревожные признаки** («да» — находка):

| Признак | Как заметить |
|---|---|
| Текст пишут под объём слов | раздувание, повторы; у Google нормы объёма нет (folklore.md) |
| Много страниц на темы без экспертизы ради трафика | разброс тем × отсутствие авторов |
| Пересказ чужого без добавленной ценности | сравнить с источниками |
| Обещание ответа, которого нет (неподтверждённые даты, слухи) | чтение |
| Дата обновлена без изменения содержания | дата × diff версий (`factdiff.py`) |
| Массовая генерация однотипных страниц | шаблон × отсутствие своих данных (`programmatic.md`) |

## Проверки

| Что | Как проверить | Severity | Движок |
|---|---|---|---|
| YMYL-страница без автора и его квалификации | `page_facts.py` + чтение | high | both |
| Подпись автора без страницы автора или страница пустая | ссылки из `page_facts` | medium | both |
| Обзор/рейтинг без методики и даты | чтение | medium | both |
| Цифры и утверждения без источника | чтение; список в отчёт | medium | both |
| Нет контактов и реквизитов на коммерческом сайте | yandex.md §7 | medium | both |
| Organization без стабильного `@id`, разные `@id` на разных страницах | JSON-LD из 3–5 страниц | low | both |
| `sameAs` ведёт на чужие, мёртвые или неофициальные профили | `http_safe.py fetch` по ссылкам + подтверждение владельца | medium | both |
| Разметка автора/организации противоречит видимому тексту | JSON-LD × HTML | medium | both |
| Название и описание бренда различаются на сайте и в профилях | сравнение | low | both |
| Дата обновления свежая, содержание не менялось | две версии + `factdiff.py` | medium | google |

## Чего не делать

- Не выдумывать авторов, должности, стаж, сертификаты, награды, отзывы, кейсы, «нашу команду экспертов». Нет данных — `[NEED: …]`.
- Не добавлять «личный опыт», «мнение», «историю», которых нет у владельца.
- Не ставить числовой «индекс E-E-A-T» и не обещать, что он влияет на позиции: оценки асессоров на ранжирование напрямую не влияют (facts-2026 §9).
- Не обещать Knowledge Panel, панель знаний Яндекса или «попадание в Wikidata».
- Не вписывать в `sameAs` профили, которые владелец не подтвердил.
- Не подменять доверие разметкой: Person/Organization без видимой информации на странице ничего не доказывают.

## Выход

1. Короткий вердикт по странице: кто / как / зачем / доверие — по строке с доказательством.
2. Таблица ЭПОС (для Яндекса) и тревожных признаков.
3. Находки по severity; список `[NEED: …]` — чего не хватает от владельца.
4. Черновик JSON-LD для Organization/Person — только из подтверждённых данных, передать в `schema.md` на проверку.
5. Покрытие и «Дальше:».
