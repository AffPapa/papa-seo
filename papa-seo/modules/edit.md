# Правка, рерайт, обновление страницы

Улучшает готовый текст, сохраняя смысл, факты и голос автора. Четыре режима: точечная правка, восстановление живого текста, пересборка из фактов и обновление старой страницы (refresh) с сохранением URL и фактов. Признаки машинного текста снимает `deai.md`, проверку утверждений делает `factcheck.md`; здесь — что и в каком порядке править.

**Когда грузить:** режимы `edit`, `refresh`; «отредактируй», «перепиши», «сократи», «улучши текст», «обнови статью», «страница устарела», «страница просела».

**Входы:** исходный текст (файл, URL или вставка); задача правки словами пользователя; профиль голоса или образцы (`voice.md`); для refresh — URL, данные GSC/Вебмастера по странице (`measure.md`), дата последнего обновления, свежие источники; `.papa-seo/project.md`.

## Шаги

1. **Сохранить исходник** отдельным файлом (`before.md`) до любой правки: без него не будет сверки.
2. **Выбрать режим** по тому, что дали, и назвать его одной строкой с доказательством:

| Режим | Признаки | Что можно менять |
|---|---|---|
| A. Точечная правка | «исправь заголовок», «сократи второй абзац» | только названное место и минимум вокруг; остальное не трогать |
| B. Живой текст | есть позиция, свои слова, неровная подача | порядок, ясность, лишнее, признаки машины; аргумент и словарь автора остаются |
| C. Пересборка | текст пустой или весь из штампов, структура не держится | писать заново из списка фактов исходника; факты те же |
| D. Обновление (refresh) | страница в индексе, устарела или просела | по согласованному плану; URL, якоря и проверенные факты сохраняются |

3. **Режим A.** Изменить названное место. Вернуть только изменённые строки с причиной в одну строку; если выбор спорный — один вариант на выбор. Серьёзная проблема в другом месте (ложное утверждение, битая ссылка) — одной строкой в конце, без правки.
4. **Режимы B и C — сначала аудит, потом правка.** Список мест: цитата → что мешает читателю → действие (`references/ru-style.md` §2). Только после списка — правка по нему, от крупного к мелкому. Для C — сначала голый список фактов, утверждений и намерений исходника; проверить, что в нём ничего не добавлено; затем текст заново по правилам жанра и голосу. Позиция, вывод, ограничение, рекомендация, которых нет в исходнике, в пересборку не добавляются.
5. **Проходы (B и C), каждый отдельно, после каждого — назад к ясности:**
   1. *Ясность.* Одна мысль — одно предложение; понятные местоимения; термин объяснён, если читатель его не знает.
   2. *Голос.* Регистр ровный, словарь автора на месте; «оборудование» не становится «решениями».
   3. *«И что?»* У каждого утверждения есть следствие для читателя. Следствие берётся из текста или данных; нет его — утверждение сокращается, а не украшается.
   4. *Доказательства.* «Лучший», «надёжный», «тысячи клиентов» — с источником. Нет источника — смягчить до проверяемого или `[NEED: …]`.
   5. *Конкретика.* Расплывчатое слово заменяется фактом из исходника или источника. Факта нет — удалить расплывчатое слово, а не подставить «примерную» цифру.
   6. *Путь к действию* (для коммерческих страниц): что сделать дальше, ясно и рядом.
6. **Де-AI** — `deai.md` поверх правки, в том же регистре.
7. **Сверка с исходником:** `python3 scripts/factdiff.py before.md after.md`. Каждое «пропало» — либо осознанно удалено (сказать, почему), либо вернуть. Каждое «появилось» — с источником. Смысловые сдвиги («риск» → «придётся», «до 30 %» → «30 %») сверять вручную по `references/ru-style.md` §9.
8. **Тест «лучше или просто иначе».** По каждой замене: если старая фраза была верной и короче — вернуть её. По каждой вставке: если без неё фраза говорит то же — убрать.

## Режим refresh (обновление страницы)

1. **Снимок до:** текст страницы, title, description, H1–H3, якоря (`id`), canonical, разметка, внутренние ссылки на страницу (`python3 scripts/page_facts.py <url> --out before.json`), запросы и клики страницы из GSC/Вебмастера за период (`measure.md`), если есть.
2. **Что держит страницу:** запросы, по которым она уже получает показы; разделы, которые под них отвечают; якоря, на которые ссылаются другие страницы. Это не трогается без причины.
3. **Что устарело:** даты, цены, версии, ссылки (404), факты, которые изменились, — по каждому источник на сегодня (`factcheck.md`).
4. **Разрыв с выдачей** (`serp.md`): таблица «подтема × наша страница × 3–5 страниц топа». Подтема у большинства топа и нет у нас — кандидат «добавить»; у одного — только если полезна читателю; ни у кого — наш возможный угол.
5. **План** — таблица разделов с пометкой «оставить / обновить / новый / убрать», черновики 2–3 вариантов title (`headlines.md`), что меняется в мета и разметке. **План согласуется с пользователем до правки** (`policies/actions.md`); без согласия — только план.
6. **Правка по плану:** факты обновляются из источников; новые разделы — по правилам `write.md`; голос — прежний.
7. **Сохранить:** URL (менять — только с 301 и по `migration.md`), якоря, на которые есть ссылки, разделы, по которым есть показы, проверенные факты исходника. Дату «обновлено» менять, только если изменилось содержание, а не запятые.
8. **Проверка после:** `factdiff.py` по тексту; `page_facts.py` — title, canonical, H1, разметка, ссылки на месте; запись, какие запросы и метрики страницы сравнить в `measure.md` и с какой даты (дата выкладки — граница периодов «до / после»). Срок «когда смотреть» не обещать: изменения проявляются неделями, точнее скажут сами данные.

## Правила

| Правило | Почему | Как проверить |
|---|---|---|
| Режим назван до правки | точечная просьба не должна превращаться в рерайт | первая строка ответа — режим и причина |
| Сначала список, потом правка | пересказ без списка дефектов делает следы машины заметнее | для B/C есть список «цитата → действие» |
| Удалять и заменять чаще, чем вставлять | вставки редактора — самый частый новый шаблон | тест «лучше или просто иначе» пройден |
| Факты исходника переносятся без искажений | правка не должна менять смысл | `factdiff.py`: каждое «пропало» объяснено |
| Конкретика — только из источника | «примерная» цифра — выдумка | у новой цифры есть источник |
| Refresh — по согласованному плану | обновление может уронить страницу | план с пометками разделов одобрен |
| URL и якоря сохраняются | на них ссылки и история страницы | `page_facts.py` до/после |
| Дата обновления — только за содержание | косметика с новой датой вводит в заблуждение | в diff есть содержательные изменения |

## Чего не делать

- Не переписывать весь текст, когда просили одну строку.
- Не менять аргумент, вывод и словарь автора на свои.
- Не добавлять эмоции, истории, «боль клиента», отзывы и цифры, которых нет в исходнике.
- Не менять URL страницы при обновлении «для свежести», не ставить год в slug.
- Не обещать рост трафика или позиций после обновления.
- Не публиковать обновлённую версию без явного «да».

## Выход

- Режим A: изменённые строки + причина + при необходимости одна альтернатива.
- Режимы B/C: список правок (цитата → действие), итоговый текст, отчёт `factdiff.py` с объяснением каждого «пропало».
- Режим D: план (таблица разделов, варианты title, что в мета и разметке) → после согласия текст, отчёт `factdiff.py`, снимок `page_facts.py` до/после, что и когда сравнить в `measure.md`.
- Строка «Дальше:».
