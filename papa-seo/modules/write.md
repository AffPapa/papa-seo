# Текст по брифу

Пишет текст страницы по готовому брифу: тип страницы, ответ в начале, раздел за разделом из фактов брифа, дисциплина источников. Модуль не добавляет опыт, мнения и истории, которых нет у автора: живость тексту дают факты и точные слова, а не вставки.

**Когда грузить:** режим `write`; «напиши статью / текст страницы / описание категории», «сделай текст по ТЗ». Для лендинга и коммерческой страницы — `landing.md`; для правки готового текста — `edit.md`.

**Входы:** бриф (`templates/brief.md`) — обязателен; нет брифа — сначала `brief.md`. Профиль голоса (`templates/voice-profile.md`) или 2–3 образца текстов площадки; `.papa-seo/project.md`; ответы эксперта; источники из таблицы фактов (файлы или URL).

## Шаги

1. **Проверить бриф.** Есть интент, тип страницы, ответ в начале, структура, таблица фактов. Каждый H2 опирается на строки фактов. Пробел в брифе — вернуться в `brief.md`, а не закрывать его текстом.
2. **Голос и регистр.** Загрузить профиль голоса (`voice.md`) или прочитать 2–3 свежих текста этой площадки: длина фраз, обращение на «вы»/«ты», термины, форматирование. Нет ни профиля, ни образцов — нейтральный регистр жанра из `references/ru-style.md` §1.
3. **Тип страницы** — по `references/page-types.md`: что на первом экране, какие блоки, какие риски. Тип из брифа не менять молча; если выдача и бриф расходятся — сказать пользователю.
4. **Первый абзац.** Ответ на главный вопрос или суть предложения — сразу, без вступления о важности темы. Если ответ зависит от условий, назвать условия.
5. **Раздел за разделом.** Каждый раздел пишется из своих строк таблицы фактов. После раздела — сверка: нет ли утверждения, которого нет в таблице. Есть — убрать или пометить `[NEED: …]`. Разделы разной длины — нормально: где фактов больше, там и текста больше.
6. **Источники.** Каждая цифра, цена, дата, цитата — из таблицы фактов, со ссылкой на источник в тексте или в списке источников (как принято на площадке). Цифры без проверенного источника не пишутся; мысль остаётся качественной («цены у сервисов различаются в разы» — только если это видно из источников) или уходит в `[NEED: …]`.
7. **Опыт и оценки.** Первое лицо, «мы проверили», «по нашему опыту», вердикт в сравнении — только если они есть в ответах эксперта или в данных заказчика. Жанр требует вердикта (сравнение, обзор, подборка), а основания нет — спросить автора, а не сочинять.
8. **Ссылки.** Внутренние — из брифа, в предложениях, где они нужны читателю; анкор описывает цель (`links.md`). Внешние — на первоисточники.
9. **Мета и заголовки** — `headlines.md`: title, H1, description согласованы с первым абзацем.
10. **Самопроверка по шагам** (каждая — отдельный проход):
    - факты: `factcheck.md` (режим «по источнику») — каждая цифра найдена в источнике;
    - де-AI: `deai.md` в режиме «свой черновик» и `python3 scripts/deai_scan.py draft.md`;
    - метрики, если их требует заказчик: `python3 scripts/text_metrics.py draft.md --keys "…"` — отчёт «оценка»;
    - структура: первый абзац отвечает; каждый H2 закрывает свой вопрос; нет раздела-пересказа в конце.
11. **Отдать** текст, список источников, открытые `[NEED: …]`, что не удалось подтвердить. Опубликовать — только по явному «да» (`policies/actions.md`).

## Правила

| Правило | Почему | Как проверить |
|---|---|---|
| Ничего не выдумывать: нет данных — опустить | выдуманный факт под чужим именем хуже пустого места | каждая цифра есть в таблице фактов брифа |
| `[NEED: …]` вместо выдуманного пруфа, отзыва, кейса | дыру видно и можно закрыть; ложь — нет | в тексте нет цифр и отзывов без источника |
| Цифры только из источника со ссылкой | читатель и ИИ-поиск цитируют проверяемое | у числа есть ссылка или строка в списке источников |
| Ответ в первом абзаце | читатель пришёл за ответом; норм длины ответа нет (`folklore.md`) | первый абзац отвечает на главный запрос |
| Длину задают факты, не норма | идеальной длины нет (facts-2026 §10) | нет абзацев без информации |
| Опыт и мнение — только от автора | иначе подмена авторства | у каждого «мы проверили» есть источник в брифе |
| Голос площадки важнее «человечности» | нарочитая разговорность — тоже шаблон | сверка с профилем голоса или образцами |
| Ключ — там, где он естественен | плотность не фактор (facts-2026 §9) | ключ в H1 и первом абзаце, если читается; без набивки |
| Неровный ритм из содержания | ритм не делают вставками | `deai_scan.py`: серии одинаковых фраз ломать перестановкой |
| Каждая проверка — отдельным проходом | общий проход пропускает | в отчёте отмечены факты, де-AI, метрики |

## Чего не делать

- Не писать без брифа «на основе общих знаний».
- Не вставлять истории «из практики», реакции, шутки, риторические вопросы, «мнение автора», которых нет у автора, ради живости.
- Не придумывать статистику, исследования, цитаты экспертов, отзывы клиентов, названия компаний «для примера».
- Не добивать объём до числа слов, не повторять ключ ради плотности, не вставлять FAQ и HowTo ради разметки.
- Не заканчивать текст разделом «Заключение», который пересказывает сказанное.
- Не обходить детекторы ИИ и не оценивать текст по их баллу: цель — точный текст, а не «неотличимость».
- Не публиковать и не отправлять в CMS без явного «да».

## Выход

- Текст в Markdown (или в формате, который задал пользователь).
- Список источников: утверждение → источник → дата.
- Открытые `[NEED: …]` и что не удалось подтвердить.
- Короткий отчёт проверок: `factcheck.md` (статусы), `deai_scan.py` (сильные признаки, кластеры), `text_metrics.py` (если требовались), с пометкой «оценка» для метрик.
- Строка «Дальше:» — обычно закрыть `[NEED]` у заказчика или передать на `edit.md`.
