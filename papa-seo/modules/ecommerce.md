# E-commerce: товары, категории, фасеты, наличие

Проверяет магазин или каталог с ценами: карточки товара, категории и листинги, фасетную навигацию, пагинацию, снятые товары и варианты, разметку Product/Offer. Общие технические проверки — `tech-audit.md`, матрица индексации — `indexing.md`, синтаксис разметки — `schema.md`.

**Когда грузить:** режимы `audit`, `page`, `fix`, `plan`; «интернет-магазин», «карточка товара», «фильтры в индексе», «нет звёзд/цены в выдаче», «товара нет в наличии — что делать со страницей».

**Входы:** 3–10 URL карточек и 3–5 URL категорий (разных типов: полная, пустая, с фильтром, с пагинацией); выгрузка URL с параметрами (CSV краулера, логи, sitemap); опционально — фид Merchant Center или товарный фид (YML) пользователя, отчёты «Товары»/«Продавцы» в GSC — только чтение.

## Шаги

1. **Тип страниц товара.** Страница продаёт товар (покупка на сайте) → merchant listing; обзор/сравнение без покупки → product snippet (facts-2026 §6). От этого зависят нужные свойства.
2. **Карточка** (`page_facts.py`): название, цена, валюта, наличие, варианты, изображения, описание, характеристики, отзывы, доставка/возврат — что видно на странице. Затем разметка: те же значения в Product/Offer. Расхождение «на странице 4 990, в разметке 3 990» — high.
3. **Гейт доказательств.** Product-разметка, отзывы, хлебные крошки — проверить на наличие во всех форматах до совета «добавить». Цена/наличие, вставленные JS-ом, — сравнить сырой и отрендеренный HTML: для товаров с быстро меняющимися ценами разметку лучше отдавать в исходном HTML (facts-2026 §2).
4. **Варианты.** Отдельные URL на вариант или один URL с выбором: canonical и разметка вариантов согласованы; вариант без своего спроса не плодит индексируемые дубли.
5. **Категория.** Есть уникальный заголовок и, если нужно, короткий полезный текст (не SEO-простыня под листингом); товары в HTML ссылками `<a href>`; пагинация по правилам facts-2026 §3 (self-canonical, ссылки на следующую страницу).
6. **Фасеты.** По выгрузке URL: какие параметры есть, сколько комбинаций, есть ли постоянный порядок, пустые комбинации отдают 404, какие фасеты имеют спрос (бренд, тип) и заслуживают индексируемой посадочной страницы, а какие закрыть (сортировка, цена-диапазон, вид). Решение — по матрице `indexing.md` и правилам facts-2026 §3. Для Яндекса параметры-дубли закрываются `Clean-param` (`references/yandex.md` §1).
7. **Снятые товары.** Временно нет в наличии → страница 200, наличие в разметке `OutOfStock`, видимая пометка и альтернативы. Снят навсегда с близкой заменой → 301 на замену; без замены → 404/410 (сохранить ссылки на категорию на странице 404). Не 301 всё на главную.
8. **Фид и разметка вместе** дают максимум охвата в Google (facts-2026 §6); фид проверяется только если пользователь его дал. Яндекс Маркет и товарные фиды Яндекса в пакете не разобраны; разметка товаров для Яндекса (строгая для OfferCatalog) — `references/yandex.md` §4.
9. **Отзывы.** Только реальные и видимые; стимулированные — с раскрытием (facts-2026 §6). Звёзды на категориях из общего рейтинга магазина — не размечать как рейтинг товара.
10. Находки → `templates/finding.schema.json`; правки шаблона карточки/категории — черновиком.

## Проверки

| Что | Как проверить | Severity | Движок |
|---|---|---|---|
| Цена/наличие в разметке не совпадают с видимыми | `page_facts`: значения против текста | high | google |
| Merchant listing без `name`, `image`, `offers`, цены > 0, валюты | facts-2026 §6 | high | google |
| `AggregateOffer` на странице прямой продажи | тип Offer | medium | google |
| Цена с символом валюты, наличие не URL-enum | формат значений | medium | google |
| Рейтинг в разметке без видимых отзывов | разметка против текста | high | google |
| Карточка без видимой цены, наличия, условий доставки и возврата | текст страницы | medium | both |
| Описание — копия от производителя у множества карточек | сравнение описаний выборки (HEURISTIC) | low | both |
| Варианты на разных URL без согласованного canonical | `page_facts` вариантов | medium | both |
| Фасетные комбинации индексируются без спроса | meta robots/canonical/sitemap выборки | high | both |
| Порядок параметров не постоянен, дубли параметров | выгрузка URL | medium | google |
| Пустая комбинация фильтров отдаёт 200 | `http_safe.py` | medium | both |
| Параметры-дубли без `Clean-param` при ориентире на Яндекс | robots × параметры | medium | yandex |
| Пагинация: canonical всех страниц на первую | `page_facts` страниц 2+ | medium | google |
| Товары в листинге без `<a href>` (только JS-подгрузка, «показать ещё» без URL) | сырой HTML | high | both |
| Снятый товар → 301 на главную или soft 404 | `http_safe.py`, текст | medium | both |
| Временно отсутствующий товар отдаёт 404 | статус + данные пользователя | medium | both |
| Категория без уникального H1/title, одинакова с фильтром | `page_facts` | medium | both |
| Внутренний поиск магазина в индексе | `indexing.md` | medium | both |
| AI-сгенерированные описания/данные товаров без пометки | facts-2026 §9 | low | google |

## Чего не делать

- Не требовать «текст на 2 000 знаков под каждым листингом».
- Не советовать индексировать все фасеты «ради длинного хвоста» без данных о спросе.
- Не выдумывать GTIN, бренды, рейтинги, сроки доставки для разметки.
- Не ставить noindex на временно отсутствующие товары с трафиком без решения владельца.
- Не запрашивать платные данные о ценах конкурентов без явной опции и пометки цены.
- Не обходить каталог целиком: выборка карточек и категорий + выгрузки.

## Выход

Находки по `templates/finding.schema.json`, `module: "ecommerce"`. Плюс: таблица карточек (URL × цена на странице × цена в разметке × наличие × отзывы × вариант); таблица фасетов (параметр × комбинаций × спрос × решение); правило для снятых товаров; черновики правок шаблонов.
