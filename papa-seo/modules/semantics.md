# Семантика: интенты, кластеры, карта «запрос → страница», каннибализация

Собирает запросы, определяет интент, группирует запросы в кластеры по общей выдаче, закрепляет за каждым кластером одну страницу и находит страницы, которые конкурируют за один запрос. Чтение конкретной выдачи и тип страницы под интент — `serp.md`; перелинковка по карте — `links.md`.

**Когда грузить:** режим `plan`; «семантическое ядро», «собери запросы», «кластеризация», «структура раздела», «какую страницу делать под запрос», «каннибализация», «две страницы на один запрос».

**Входы:** тема и тип сайта; список запросов (от пользователя, из выгрузки GSC «Эффективность», Вебмастера «Запросы», Wordstat — CSV пользователя); регион и язык; список существующих URL раздела (sitemap или корпус). Частотность — только из источника с периодом; нет источника — `null`.

## Шаги

1. **Источники спроса, бесплатно сначала.**
   - Свои данные: GSC и Вебмастер — запросы, по которым сайт уже показывается (самый честный источник, но только про видимое).
   - Ручной Wordstat (`wordstat.yandex.ru`): пользователь выгружает сам; операторы (`"…"`, `!`, `-`) записывать рядом с цифрой, иначе цифру нельзя перепроверить.
   - Подсказки и «похожие запросы» из выдачи — как список формулировок, без частотности.
   - Платно, по ключу пользователя: Wordstat API, Yandex Search API (цены `references/yandex.md` §11), DataForSEO и аналоги. До запуска назвать число запросов и цену, получить «да».
2. **Нормализация.** Нижний регистр, ё → е, пробелы, дубли; русские словоформы свести к основе (простой стемминг или лемматизация; `text_metrics.py` даёт основы). Пометить регион и устройство, если они разные в источниках.
3. **Интент каждого запроса:** информационный / коммерческий (сравнение, выбор) / транзакционный (купить, заказать, цена) / навигационный (бренд, вход) / локальный. Сомнительные — проверить по выдаче (`serp.md`): что показывают и чего хочет человек. Типичные ловушки: «X для Y» ищут аксессуар, а не Y; «своими руками», «как сделать» — информационный; «ремонт», «замена» — человек уже владеет вещью. Нецелевые запросы — в отдельный список с причиной, не удалять молча.
4. **Пре-группировка** (экономит сравнения пар): внутри одного интента — по общей основе ключевого слова. Пары из разных интентов по умолчанию не объединять. Эта стадия только предлагает кандидатов — решение даёт выдача.
5. **Кластеризация по выдаче.** Для каждого запроса — топ-10 органических URL (без рекламы и колдунщиков), URL нормализовать (протокол, слэш, лишние параметры). Перед подсчётом убрать вездесущие домены, которые есть почти в каждой выдаче (энциклопедии, маркетплейсы, агрегаторы). Число общих URL у пары:

   | Общих URL в топ-10 | Связь | Решение |
   |---|---|---|
   | 7–10 | один запрос по сути | одна страница |
   | 4–6 | один кластер | одна страница или соседние страницы кластера |
   | 2–3 | смежные | разные страницы, связать ссылками |
   | 0–1 | разные | разные кластеры |

   Пороги — эвристика метода (claude-seo), помечать `HEURISTIC`. Пограничные 3–4: смотреть совпадение доменов, интент и форму выдачи (видео, карты, товары — значит другой тип страницы). Выдачу кэшировать в рамках сессии, не запрашивать один запрос дважды.
6. **Чья выдача.** Для рунета решает выдача Яндекса. Встроенный веб-поиск агента может отдавать не российскую и не яндексовую выдачу — проверить и написать в отчёте, какая выдача использована. Без Yandex Search API (платно) или выгрузки пользователя кластеры по Яндексу помечать `likely`, а не `confirmed`.
7. **Карта «запрос → страница».** Файл `page_map.csv` со столбцами: `cluster, query, intent, demand, demand_source, period, target_url, url_status (existing|new|merge), page_type, notes`. Каждый кластер — ровно одна целевая страница. `target_url` для `existing` — только реально существующий URL (200, индексируемый, проверено `page_facts.py`); для `new` — предложенный путь с пометкой «предложение». CSV-ячейки, начинающиеся с `=`, `+`, `-`, `@`, экранировать апострофом.
8. **Каннибализация** (по выгрузке GSC/Вебмастера «запрос × страница» за один период):
   - кандидаты — запросы, по которым показы получают ≥ 2 URL сайта;
   - отсеять норму: главная + раздел по брендовому запросу, разные интенты, разные регионы;
   - для оставшихся проверить, совпадает ли интент страниц и меняется ли ранжирующий URL от недели к неделе;
   - решение на выбор: разделить интенты (переписать одну страницу под свой запрос), объединить содержимое с 301 на сильную, перелинковать с главной страницы кластера, canonical — только для настоящих дублей. Не ставить 301 по одной эвристике: решение с трафиковых URL — черновиком и после согласия (policies/actions.md).
9. **Гейт доказательств.** «Страницы под кластер нет» — только после поиска по sitemap/корпусу и `site:`-проверки как подсказки (не доказательство). Каннибализация — только по данным «запрос × страница», не по похожим title.
10. Выход в `page_map.csv` + короткий отчёт; находки — `policies/evidence.md`.

## Проверки

| Что | Как проверить | Severity |
|---|---|---|
| Частотность без источника и периода | столбцы `demand_source`, `period` | high |
| Кластер без целевой страницы или с двумя | `page_map.csv` | medium |
| `target_url` не существует или не индексируется | `page_facts.py` | high |
| Запросы разных интентов слиты в одну страницу | интент × выдача | medium |
| Отдельные страницы под словоформы и перестановки одного запроса | общие URL 7–10 | high |
| Два URL сайта делят показы по одному запросу с одним интентом | выгрузка «запрос × страница» | medium |
| Кластеры для рунета построены по не яндексовой выдаче без пометки | источник выдачи | medium |

## Чего не делать

- Не выдумывать частотность, сложность, «потенциальный трафик», CTR.
- Не использовать «LSI-слова» и плотность ключа как фактор (folklore.md).
- Не кластеризовать только по похожести слов: «одинаково звучат» не значит «одна выдача».
- Не плодить страницы под каждую формулировку: это путь к scaled content abuse (facts-2026 §9) и к каннибализации.
- Не обходить сайт ради списка URL — брать sitemap, корпус или выгрузку.
- Не запускать платные запросы без названной цены и «да».

## Выход

1. `page_map.csv` (кластер → запросы → интент → спрос с источником → целевая страница).
2. Таблица кластеров: название, интент, тип страницы, целевой URL, статус; отдельный список нецелевых запросов с причинами.
3. Каннибализация: запрос, конкурирующие URL, данные, предложенное решение, `approval_required: true`.
4. Какая выдача использована, сколько запросов сравнено по выдаче, что помечено `likely`.
5. «Дальше:» — обычно `serp.md` для сомнительных интентов или `brief.md` для новой страницы.
