# Внутренние ссылки

Строит граф внутренних ссылок из готовых данных (без обхода сайта), находит сироты, глубокие и слабо связанные страницы, плохие анкоры, битые и редиректные ссылки, и готовит точный план вставок: донор → цель → анкор → предложение. Карта «кластер → страница» — из `semantics.md`. Внешние ссылки — `backlinks.md`.

**Когда грузить:** режим `links`; «перелинковка», «сироты», «страница не получает ссылок», «глубина вложенности», «анкоры», «куда поставить ссылку на новую статью».

**Входы (одно из):**
- CSV рёбер `from,to,anchor,region` — из краулера пользователя, корпуса страниц или базы сайта (`region`: nav | header | footer | breadcrumb | aside | main | other);
- папка с HTML-файлами страниц (корпус);
- для одной новой страницы — её URL/черновик и список кандидатов-доноров (до 20 URL).

Плюс: список URL из sitemap (для сирот), выгрузка GSC «Эффективность» по страницам (какие доноры видимы), отчёт Вебмастера/GSC о внутренних ссылках, если есть; `page_map.csv` из `semantics.md`.

## Шаги

1. **Граф без обхода.** `python3 scripts/link_graph.py edges.csv --pages sitemap_urls.txt --out graph.json` или для корпуса `python3 scripts/link_graph.py --html-dir pages/ --base-url https://site/ --pages sitemap_urls.txt --out graph.json`; таблица узлов для таблиц — `--csv-out nodes.csv`. Скрипт считает входящие ссылки, глубину от главной, внутренний PageRank, сироты; работает потоково. Если данных нет — попросить выгрузку краулера или корпус; массовый обход только по явной просьбе, в один поток (SKILL.md §3).
2. **Полнота графа.** Записать, из чего граф: сколько страниц, все ли разделы, есть ли страницы, на которые ссылаются, но которых нет в данных. «Страница — сирота» и «на сайте нет ссылок на X» — только при полном графе; иначе «в проверенных N страницах ссылок нет».
3. **Регион ссылки.** Считать входящие из основного контента (`main`) отдельно от сквозных (`nav`, `footer`, `header`). Страница с сотней ссылок из подвала и ни одной из текста — слабо связана по смыслу.
4. **Метрики** (все — `DETERMINISTIC`, относительные внутри сайта, не PageRank Google):
   - входящие из `main` и всего;
   - глубина кликов от главной;
   - внутренний PageRank — чтобы видеть, куда стекается вес, а не как прогноз позиций;
   - сироты: URL из sitemap или `page_map.csv`, у которых 0 входящих в графе.
5. **Анкоры.** Пустые, «подробнее», «здесь», «читать далее», «click here», голый URL — находка; анкор должен говорить, что за ссылкой. Один и тот же анкор, ведущий на две разные страницы, — сигнал каннибализации (`semantics.md`). Долей «точных/частичных» анкоров не задавать: таких норм нет.
6. **Технические дефекты ссылок** (по выборке целей, `page_facts.py` или данным краулера): ссылки на 4xx, на URL с редиректом (ставить конечный адрес), на `noindex`, на неканонические версии, внутренние `nofollow`, ссылки только в JS без `<a href>`.
7. **Что связывать.** Для каждой цели (сирота, глубокая страница, страница кластера из `page_map.csv`):
   1. стоит ли ей ранжироваться? Нет (устарела, дубль) — не ссылки, а 301 на замену или `noindex` (`indexing.md`), решение — через согласие;
   2. главная страница её кластера — ссылается ли она на цель и цель на неё;
   3. 2–5 доноров, с которых читатель логично пришёл бы: та же тема, видимые в поиске (по GSC), сами индексируемые;
   4. место и анкор.
8. **Точная вставка.** Для каждой ссылки:

   | Донор (URL) | Цель (URL) | Анкор | Где: дословное предложение донора | Новое предложение | Регион | Приоритет |
   |---|---|---|---|---|---|---|

   - донор и цель **существуют**: 200, индексируемые, canonical на себя — проверено `page_facts.py`; URL не придумывать и не собирать «по шаблону»;
   - «дословное предложение» найдено в HTML донора (цитата из текста), чтобы правку можно было найти и проверить;
   - анкор — естественная часть предложения; если подходящего предложения нет — предложить одно новое предложение и пометить `approval_required: true`;
   - не больше одной ссылки на одну цель с одного донора; не вставлять в навигацию и подвал то, что должно быть в тексте.
9. **Гейт доказательств.** Перед «добавьте ссылку с A на B» — проверить, что её там нет (поиск `href` цели в HTML донора, включая относительные варианты).
10. Находки — `policies/evidence.md`; план вставок — черновик (policies/actions.md), правки в CMS не делать без «да».

## Проверки

| Что | Как проверить | Severity |
|---|---|---|
| Целевая (деньги, кластер) страница — сирота при полном графе | `link_graph.py` | high |
| Целевая страница получает ссылки только из nav/footer | регион входящих | medium |
| Глубина целевой страницы заметно больше, чем у её кластера | `link_graph.py` | medium |
| Внутренние ссылки на 4xx | выборка целей | high |
| Внутренние ссылки на редиректы | выборка целей | low |
| Ссылки на `noindex`/неканонические версии из основного текста | `page_facts.py` целей | medium |
| Внутренний `nofollow` | атрибуты ссылок | low |
| Ссылки только через JS-обработчики, без `href` | `page_facts.py` | medium |
| Пустые и общие анкоры | список анкоров | low |
| Один анкор → разные цели | группировка анкоров | medium |
| Главная страница кластера не ссылается на свои страницы | граф × `page_map.csv` | medium |

## Чего не делать

- Не придумывать URL доноров и целей; только проверенные существующие адреса.
- Не обходить сайт ради графа без явного запроса; брать CSV, корпус или выгрузку.
- Не задавать квоты «N ссылок на страницу» и проценты анкоров как норму.
- Не обещать рост трафика или позиций от перелинковки в процентах и сроках.
- Не ставить сквозные блоки «похожие статьи» с сотнями ссылок вместо осмысленных вставок.
- Не править тексты доноров молча: каждая вставка видна в плане и проходит согласие.

## Выход

1. Сводка графа: источник, число страниц, полнота, сколько сирот, распределение глубины.
2. Таблица проблемных страниц (цель, входящие main/всего, глубина, PageRank, проблема).
3. План вставок (таблица шага 8), упорядоченный по приоритету: сначала целевые сироты, затем глубокие, затем усиление кластеров.
4. Список технических дефектов ссылок.
5. Покрытие и «Дальше:».
