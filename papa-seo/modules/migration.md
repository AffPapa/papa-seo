# Миграция: смена URL, домена, CMS, дизайна

Планирует и проверяет переезд так, чтобы каждый старый URL с трафиком или ссылками вёл одним 301 на правильный новый, а поисковики узнали о переезде: инвентарь до, карта редиректов, проверка стенда, выкладка, наблюдение после, критерии отката. Правила редиректов — facts-2026 §3.

**Когда грузить:** режимы `plan`, `fix`, `audit`; «переезжаем на новый домен», «меняем CMS», «новая структура URL», «редизайн», «упал трафик после переезда».

**Входы:** список старых URL (sitemap, выгрузка GSC «Страницы», Вебмастер «Страницы в поиске», CSV краулера); список новых URL или правило их построения; страницы с внешними ссылками (GSC «Ссылки», Вебмастер, CSV — `backlinks.md`); дата переезда; стенд (URL стейджинга, если доступен и пользователь разрешил).

## Типы переезда

| Тип | Что меняется | Смена адреса в GSC | Яндекс |
|---|---|---|---|
| Домен или поддомен | хост | да (facts-2026 §3) | переезд в Вебмастере, references/yandex.md |
| HTTP → HTTPS, www ↔ без www | протокол/вариант хоста | для www/без www — см. facts-2026 §3 | references/yandex.md |
| Структура URL на том же хосте | пути | нет | нет специального инструмента |
| CMS / шаблоны при тех же URL | HTML, разметка, ссылки | нет | нет |
| Слияние сайтов / разделов | хосты и пути | при смене домена — да | references/yandex.md |

## Шаги

1. **Инвентарь до переезда.** Сохранить снимок: все известные URL; по каждому — статус, canonical, title, H1, meta robots, разметка (`page_facts.py` по выборке, ≤ 20 URL за проход с паузой); клики и показы за период (GSC/Вебмастер, если есть); внешние ссылки на URL; текущие robots.txt, sitemap, редиректы. Это базовая линия для сравнения.
2. **Приоритет.** Отметить URL с трафиком, с внешними ссылками, с конверсиями и с хорошими позициями — их проверять поштучно. Остальные — по правилу и выборке.
3. **Карта редиректов** CSV `old_url,new_url,type,reason`: каждый старый URL → наиболее близкий по смыслу новый, 301 (или 308). Без аналога — 404/410, не на главную. Учесть варианты: слэш, регистр, `index.html`, параметры, пагинацию, старые редиректы (сплющить цепочки до одного шага). Проверка: нет петель, нет целей с 3xx/4xx, нет массового слива на одну страницу.
4. **Проверка стенда** (если есть и разрешено): на выборке из карты — новый URL отдаёт 200, canonical на себя, meta robots не `noindex` (типичная ошибка — перенос `noindex` или `Disallow: /` со стенда), title/H1/разметка не потеряны против снимка шага 1, внутренние ссылки ведут на новые URL, а не через редиректы. hreflang обновлён (`international.md`).
5. **Выкладка.** Включить редиректы и новый сайт одновременно; robots.txt нового сайта открыт; новый sitemap с новыми URL; при смене домена — инструмент смены адреса в GSC и переезд в Вебмастере (шаги — references/yandex.md). Старый sitemap можно оставить на время, чтобы видеть, как уходят старые URL (facts-2026 §3).
6. **Проверка после выкладки.** `python3 scripts/http_safe.py fetch <old_url>` по всем приоритетным URL и выборке остальных: один шаг 301 на ожидаемый `new_url`. Сравнить новые страницы со снимком: что пропало (title, текст, разметка, ссылки). Ошибки 404/5xx в отчётах GSC/Вебмастера и в логах (`logs.md`).
7. **Наблюдение.** Метрики сравнивать с базовой линией по одинаковым периодам (неделя к неделе, тот же день недели); переиндексация занимает недели (facts-2026 §3) — не делать выводов по первым дням. Что проверять и когда — таблица ниже.
8. **Откат.** Критерии и порог задаёт владелец до переезда (например: массовые 5xx, сломанные редиректы приоритетных URL, недоступные конверсионные страницы). Агент не придумывает проценты падения трафика как норму.
9. **Гейт доказательств.** «Редирект сломан» — по ответу сервера, не по таблице. «Трафик упал из-за переезда» — только после проверки, что дата падения совпадает с датой переезда, и исключения сезонности и апдейтов.
10. Редиректы держать долго, ориентир — facts-2026 §3. Внутренние ссылки и важные внешние — обновить на новые URL.

## Наблюдение после переезда

| Когда | Что проверить | Источник |
|---|---|---|
| День 0–1 | приоритетные URL: один 301 на ожидаемый адрес; новые — 200; robots.txt и sitemap нового сайта; ошибки сервера | `http_safe.py`, логи |
| Неделя 1 | 404/5xx в отчётах; старые URL с ссылками; сравнение со снимком | GSC, Вебмастер, `page_facts` |
| Недели 2–8 | индексация новых URL, уход старых, клики/показы против базовой линии | GSC, Вебмастер |
| После стабилизации | оставшиеся старые URL в индексе, цепочки, внутренние ссылки на старые адреса | выгрузки, `link_graph.py` |

## Проверки

| Что | Как проверить | Severity | Движок |
|---|---|---|---|
| Старый URL с трафиком или ссылками отдаёт 404 | `http_safe.py` по карте | critical | both |
| Массовый редирект на главную или категорию вместо соответствия | цели в карте | high | both |
| Цепочка из нескольких редиректов, петля | `chain` | high | both |
| 302/307 при постоянном переезде | тип ответа | high | both |
| На новом сайте остался `noindex` или `Disallow: /` со стенда | `page_facts`, `robots_check.py` | critical | both |
| Canonical новых страниц указывает на старый домен/стенд | `page_facts` | critical | both |
| Пропали title/H1/текст/разметка против снимка | сравнение снимков | high | both |
| Внутренние ссылки ведут на старые URL через редиректы | `link_graph.py` / `page_facts` | medium | both |
| hreflang/sitemap со старыми URL | `sitemap_check.py`, `page_facts` | medium | both |
| При смене домена не сделан переезд в GSC/Вебмастере | вопрос пользователю; сам агент в кабинеты не входит | high | both |
| Редиректы сняты раньше срока | ответ старых URL | high | both |

## Чего не делать

- Не обещать «просадку 10–30 % и восстановление за 2–3 месяца» (references/folklore.md).
- Не сливать все удалённые страницы на главную.
- Не переносить robots.txt и meta robots со стенда.
- Не менять URL и контент одновременно без нужды: так труднее понять причину изменений.
- Не нажимать «переезд» в GSC/Вебмастере за пользователя и не менять настройки кабинетов.
- Не проверять тысячи редиректов параллельно на продакшене: выборка и приоритетные, последовательно, или проверка карты по логам.

## Выход

Находки по `templates/finding.schema.json`, `module: "migration"`. Плюс: карта редиректов CSV (с колонкой проверки `status_after`), снимок «до» по приоритетным URL, чек-лист выкладки, план наблюдения с датами, критерии отката от владельца.
