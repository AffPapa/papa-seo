# On-page: title, description, заголовки, первый экран, изображения

Проверяет, что страница ясно говорит поисковику и человеку, о чём она: `<title>`, meta description, H1–H6, первый экран, Open Graph, изображения (alt, размеры, форматы, lazy/LCP). Тексты заголовков переписывает `headlines.md`, разметку — `schema.md`, скорость — `performance.md`.

**Когда грузить:** режим `page`, часть `audit`; «проверь страницу», «почему Google переписал title», «оптимизируй мету», «проверь картинки».

**Входы:** URL или HTML-файл; целевой запрос или интент страницы (если пользователь дал); тип страницы (`references/page-types.md`). Опционально: запросы страницы из GSC/Вебмастера (чтение) — чтобы сверить title с реальным спросом.

## Шаги

1. `python3 scripts/page_facts.py <URL|файл> --out facts.json` — title, meta, robots, H1–H6, первый блок текста, OG, изображения (src, alt, width/height, loading, fetchpriority, srcset), ссылки. Там же блок `checks`: по строке на каждый параметр (Open Graph и Twitter Card, viewport, `lang`/`dir`, иконки, заголовки безопасности, смешанный контент, ресурсы, атрибуты картинок, таблицы, списки, дубли `id`, якоря, формы, пагинация) со статусом `pass/warn/fail/info/skip` и источником требования. `skip` значит «нет данных», а не «хорошо».
2. **Тип страницы и интент.** Взять из запроса пользователя или `references/page-types.md`; если неясно — `serp.md`. Без интента не судить, «подходит ли» title.
3. **Title.** Есть, один, не пустой, уникален в выборке, совпадает с главной темой и H1 по смыслу, бренд коротко, без набивки и шаблонных повторов (правила — facts-2026 §5). Длину не считать нарушением: обрезка зависит от устройства, лимита нет. Если есть данные GSC — сравнить с запросами, по которым страница реально показывается.
4. **Description.** Есть, своя для страницы, описывает содержимое, не повторяет title. Google может взять текст со страницы — это не дефект; дефект — шаблонная или чужая description.
5. **Заголовки.** Один видимый главный заголовок (обычно H1), иерархия читается, H2 описывают разделы, а не «Введение/Заключение». Пропуск уровня — low, не ошибка ранжирования.
6. **Первый экран.** Главная мысль и ответ на интент видны без прокрутки и без клика по вкладке/аккордеону; нет перекрывающих интерстициалов. Проверять по сырому HTML и, если есть, по скриншоту/рендеру.
7. **Изображения.** Контентные `<img>` с осмысленным alt; декоративные — пустой alt или `role="presentation"`. У всех — `width`/`height` или `aspect-ratio`. LCP-картинка не на lazy, приоритет у одной-двух (facts-2026 §7). Современные форматы и `srcset` — рекомендация, не ошибка.
8. **Гейт доказательств.** Каждое «нет X» — по `page_facts`, а не на глаз. Если H1 или title появляются только после JS — это находка `tech-audit.md`, не on-page.
9. **Яндекс.** Правила заголовка и описания сниппета у Яндекса свои, выводы по Google на него не переносить; для коммерческих страниц — видимые цена, контакты, условия (`references/yandex.md` §3, §7). Отмечать `engine` у каждой находки.
10. Находки → `templates/finding.schema.json`; переписанные варианты title/description — только черновиком, без публикации.

## Проверки

| Что | Как проверить | Severity | Движок |
|---|---|---|---|
| Нет `<title>` или пустой | `page_facts.title` | high | both |
| Несколько `<title>` | счётчик тегов | medium | both |
| Одинаковый title у разных страниц выборки | сравнение по списку URL | medium | both |
| Title не о том, о чём страница / противоречит H1 | сравнение title, H1, первого абзаца с интентом | medium | both |
| Набивка ключами, повтор слов, капслок | токены title | medium | both |
| Шаблонный хвост на всех страницах длиннее содержательной части | сравнение по выборке | low | google |
| Title на другом языке, чем контент | язык title против текста | medium | both |
| Нет description или одна на много страниц | `page_facts.meta.description` + выборка | low | both |
| Description повторяет title слово в слово | строковое сравнение | low | both |
| Нет видимого главного заголовка; H1 пустой или логотип | `page_facts.headings` | medium | both |
| Несколько H1 с разной темой | список H1 | low | both |
| Ответ на интент не на первом экране, спрятан во вкладку | позиция первого содержательного абзаца | medium | both |
| Полноэкранный интерстициал на мобильном при входе из поиска | рендер/скриншот; HEURISTIC без рендера | medium | google |
| Контентное изображение без alt или с alt = имя файла | `page_facts.images` | low | both |
| alt набит ключами | токены alt | low | both |
| Изображение без width/height (риск CLS) | атрибуты `<img>` | medium | google |
| LCP-кандидат с `loading="lazy"` | первая крупная картинка первого экрана | high | google |
| `fetchpriority="high"` на многих картинках | счётчик | low | google |
| Картинка в CSS-фоне вместо `<img>` для важного контента | `page_facts`: изображения против фоновых | low | google |
| Нет `og:title`/`og:image` (превью в соцсетях и мессенджерах) | `page_facts.og` | low | both |
| Коммерческая страница без видимой цены/контактов/условий | текст первого экрана и подвала | medium | yandex |
| Текст для поисковика спрятан (display:none, белым по белому) | `page_facts`: скрытые блоки | high | both |

## Как формулировать правку title

- Давать 2–3 варианта, не один «правильный»; каждый — с причиной из данных (запросы GSC, интент, тип страницы).
- Числа, годы, ГЕО, цены — только если они есть на странице или в данных пользователя. Не придумывать «2026», «топ-10», «лучшие», если страница этого не доказывает.
- Сохранять бренд и смысл H1; не делать кликбейт.

## Чего не делать

- Не считать «длиннее 60 символов» и «description длиннее 160» ошибкой (references/folklore.md).
- Не требовать минимального числа слов и плотности ключа.
- Не рекомендовать менять alt всем картинкам ради ключей.
- Не предлагать «добавить H1», если он есть, но выглядит не как H1 визуально — проверять разметку.
- Не переписывать текст страницы в этом модуле: это `edit.md`.
- Не утверждать, что Google «покажет» конкретный title: он выбирает сам (facts-2026 §5).

## Выход

Находки по `templates/finding.schema.json`, `module: "on-page"`. Плюс короткая карточка страницы: title / H1 / description / первый абзац (как есть), интент, 2–3 варианта title и description черновиком с обоснованием, список изображений с проблемами (src, что не так, как исправить).
