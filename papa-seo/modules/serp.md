# Выдача: интент, тип страницы, честные сравнения

Читает выдачу по запросу и отвечает на вопрос: какую страницу поисковик считает ответом и подходит ли наша. Главная ошибка, которую ищем, — неверный тип страницы (статья там, где выдача показывает каталоги, или наоборот). Отдельно — как делать страницы сравнения и «альтернативы X», не теряя честности. Кластеры запросов — `semantics.md`; тексты — `brief.md`, `write.md`.

**Когда грузить:** режимы `plan`, `brief`, `page`; «почему не ранжируется при хорошей странице», «какой тип страницы нужен», «что в топе», «разбери конкурентов по запросу», «страница сравнения», «X vs Y», «альтернативы X».

**Входы:** запрос (или запросы кластера), регион, движок (Яндекс / Google); URL нашей страницы, если есть; выдача — одним из способов ниже.

## Откуда брать выдачу

| Способ | Цена | Надёжность |
|---|---|---|
| Скриншоты или сохранённые HTML выдачи от пользователя (его регион, его браузер) | бесплатно | высокая для его региона |
| Встроенный веб-поиск агента | бесплатно | средняя: может отдавать не ту страну и не тот движок — проверить и записать |
| Yandex Search API | платно, `references/yandex.md` §11 | высокая для Яндекса |
| DataForSEO и аналоги | платно, по ключу пользователя | высокая для Google |

Выдачу Яндекса и Google не смешивать. Скрейпить выдачу напрямую, обходить капчу и подставлять cookie — нельзя.

## Шаги

1. **Собрать топ-10 органики** по запросу: URL, домен, тип страницы, формат (лонгрид, список, сравнение, каталог, карточка, инструмент, видео, форум), видимые признаки свежести. Типы страниц — по `references/page-types.md`.
2. **Особые блоки выдачи.** Google: AI Overview, «Похожие вопросы», видео, картинки, карты, товары, панель знаний. Яндекс: ответ Алисы AI, быстрый ответ, колдунщики (карты, товары, видео, картинки), объектный ответ. Для каждого — кто его занимает. Таблица:

   | Запрос | Блок | Кто занимает | Наша страница | Реально ли | Почему |
   |---|---|---|---|---|---|

3. **Консенсус по типу страницы** (эвристика метода, `HEURISTIC`): доля одного типа в топ-10 — больше 60 % — сильный консенсус, от 40 до 60 % — смешанный, меньше 40 % — раздробленный. При раздробленной выдаче поисковик не уверен в интенте — есть место для другого формата.
4. **Тип нашей страницы** — определить по живому HTML (`python3 scripts/page_facts.py <url>`), а не по URL или названию шаблона.
5. **Несовпадение типа:**

   | Наша страница | Выдача хочет | Severity | Что делать |
   |---|---|---|---|
   | статья | каталог/карточки товаров или услуг | critical | отдельная коммерческая страница; статья — в поддержку |
   | статья | сравнения | high | перестроить в сравнение с таблицей и выводом |
   | карточка/лендинг | информационные материалы | high | статья под интент + ссылка на карточку |
   | лендинг | инструменты, калькуляторы | high | инструмент, если он реально полезен |
   | услуга | локальная выдача, карты | medium | `local.md`: карточки организации, адрес, регион |
   | совпадает | — | — | работать с содержанием и доверием (`eeat.md`) |

6. **Задачи пользователя из выдачи.** «Похожие вопросы», подсказки, формулировки заголовков в топе, тексты рекламы — показывают, что ещё человек хочет узнать и что его останавливает. Записать как список вопросов для брифа, без «персон» с баллами.
7. **Чего в топе нет.** Собственные данные, замеры, методика, свежие цены, честные минусы — то, что можем дать только мы. Это главный аргумент для брифа, а не объём текста.
8. **Гейт доказательств.** «В выдаче одни каталоги» — только по реально просмотренным 10 результатам с указанием источника и даты. Меньше 5 результатов — вывод `hypothesis`.

## Страницы сравнения и «альтернативы X»

- Каждое утверждение о чужом продукте — проверяемое по публичному источнику, со ссылкой. Цены и тарифы — с пометкой «на ДД.ММ.ГГГГ».
- Своё участие раскрыто: какой продукт наш, есть ли партнёрские ссылки.
- Сильные стороны конкурентов признаны; минусы — фактами, без оценочных ярлыков. Ложные и порочащие утверждения недопустимы.
- Методика видна: по каким критериям сравнивали, что тестировали сами, что взяли из документации.
- Рейтинг в разметке — только если он виден на странице и посчитан по реальным данным (`schema.md`).
- Данных о конкуренте нет — `[NEED: источник]`, ячейку не заполнять догадкой.
- Связать сравнения между собой («A vs B» ↔ «A vs C») и с карточками продуктов (`links.md`).

## Проверки

| Что | Как проверить | Severity |
|---|---|---|
| Тип нашей страницы не совпадает с сильным консенсусом выдачи | шаги 3–5 | critical/high |
| Вывод о выдаче без указания движка, региона, даты, источника | отчёт | medium |
| Выдача Google использована как выдача Яндекса | источник | medium |
| Страница сравнения без методики, дат цен, раскрытия участия | чтение | high |
| Утверждения о конкурентах без ссылок на источник | чтение | high |
| Разметка рейтинга без видимых реальных отзывов | `page_facts.py` + HTML | high |

## Чего не делать

- Не ставить цель «написать больше слов, чем в топе» и не мерить объём выдачи как норму (folklore.md).
- Не ставить норму длины ответа под заголовком ради сниппета (folklore.md) и не советовать FAQ/HowTo-разметку ради блоков выдачи (facts-2026 §6).
- Не обещать «нулевую позицию», ответ Алисы или AI Overview.
- Не копировать структуру и формулировки конкурентов; брать из выдачи интент и пробелы, а не текст.
- Не вставлять в заголовок год и «лучшие/топ», если на странице нет свежего и реально ранжированного списка.

## Выход

1. Сводка выдачи: движок, регион, дата, источник; топ-10 с типами; блоки и кто их держит.
2. Вердикт по типу страницы: совпадает / несовпадение (severity) и что делать.
3. Вопросы пользователя и пробелы топа — список для `brief.md`.
4. Для сравнений — чек-лист честности с отметками.
5. «Дальше:».
