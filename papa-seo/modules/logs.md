# Логи доступа: что реально запрашивают боты

Отвечает по логам сервера или CDN, какие боты приходят, что они сканируют, какие ответы получают и куда уходит обход; отделяет настоящих Googlebot/YandexBot от подделок по User-Agent. Логи — единственное место, где видно поведение краулеров, а не настройки.

**Когда грузить:** режимы `audit`, `fix`, `geo`; «что сканирует Googlebot», «бюджет обхода», «бот грузит сервер», «ходят ли AI-боты», «почему новые страницы не находятся».

**Входы:** файлы логов (combined/common Apache/Nginx, JSON-строки Caddy/Nginx/Cloudflare Logpush, `.gz`) за период; список URL-групп (`indexing.md`); опционально — отчёт «Статистика сканирования» GSC и Вебмастера. Логи содержат персональные данные (IP, иногда параметры): обрабатывать локально, IP в отчёт не выводить.

## Шаги

1. **Формат и окно.** Определить формат по первым строкам, период (первая и последняя метка времени), часовой пояс, долю нераспознанных строк. Записать ограничения: лог origin не видит запросов, отданных из кэша CDN; ротация и сэмплинг занижают счёт; «не найден в логах» значит «не найден в этом окне», а не «не ходит».
2. **Чтение потоком.** Обрабатывать построчно, не загружая лог целиком в память; большие периоды — по файлу за раз, с агрегацией счётчиков.
3. **Классификация по User-Agent:** поисковые (Googlebot и его варианты, YandexBot и роботы Яндекса, Bingbot), AI по уровням (search / training / user_fetch — `references/ai-bots.yaml`), прочие боты, люди. UA — только заявление.
4. **Проверка подлинности.** Выбрать уникальные IP заявленных поисковых ботов и `python3 scripts/bot_verify.py --log <лог> --only-claimed --out verify.json` (или список IP аргументами): обратный DNS → домен из списка → прямой DNS → тот же IP (Google, Bing — facts-2026 §11; Яндекс — references/yandex.md). Для AI-ботов, где вендор публикует диапазоны IP, — сверка с диапазонами (facts-2026 §10–11). Неподтверждённые хиты — отдельной строкой «заявлен Googlebot, не подтверждён».
5. **Разрезы для подтверждённых ботов:** запросы по дням; по группам URL; по статусам (2xx/3xx/4xx/5xx); по типам ресурсов (HTML, JS/CSS, картинки, API); доля параметрических URL; топ запрашиваемых путей; время ответа, если оно в логе.
6. **Сопоставить с намерением.** Сравнить, что сканируется, с матрицей индексации: обход уходит на фильтры, поиск, служебные URL; целевые группы почти не сканируются; новые URL не запрашиваются после публикации; боты получают 5xx/429 или долгие ответы в часы нагрузки.
7. **Гейт доказательств.** «Googlebot тратит бюджет на фильтры» — только по подтверждённым хитам и с долей от общего обхода. «AI-бот X не ходит» — только с оговоркой окна и CDN. Выводы о краулинговом бюджете — с учётом размера сайта (facts-2026 §1): для малого сайта бюджет обычно не проблема.
8. **Нагрузка от ботов.** Если боты грузят сервер: какие (подтверждённые или поддельные), в какие часы, какие URL. Меры — черновиком: блок подделок на уровне сервера/CDN, robots.txt для честных, скорость обхода в Вебмастере для Яндекса (references/yandex.md). Google снижает обход сам при 5xx/429 (facts-2026 §1).
9. Находки → `templates/finding.schema.json`, `source_type: "user_file"`.

## Проверки

| Что | Как проверить | Severity | Движок |
|---|---|---|---|
| Подтверждённый Googlebot/YandexBot получает 5xx на целевых URL | статусы по группам | critical | both |
| Боты получают 429/503 в часы пик | статусы по часам | high | both |
| Большая доля обхода — параметры, фильтры, внутренний поиск | доля по группам | high | both |
| Целевая группа почти не сканируется | хиты по группам против числа URL | medium | both |
| Новые URL не запрашиваются через дни после публикации | первый хит после даты публикации | medium | both |
| Обход 404 на старых URL с ссылками (нет редиректа) | топ 404 подтверждённых ботов × `backlinks.md` | high | both |
| Цепочки 3xx в обходе | повторные 301 на один путь | medium | both |
| Боты не получают CSS/JS (403/Disallow) | статусы ресурсов | high | google |
| Хиты с UA Googlebot/YandexBot, не прошедшие проверку DNS | `bot_verify.py` | medium (info, если мало) | both |
| AI-бот уровня training ходит при запрете в robots.txt | robots × подтверждённые хиты | medium | ai |
| user_fetch-боты: robots.txt может не применяться — проверять ожидания владельца | `references/ai-bots.yaml` | info | ai |
| Медленные ответы ботам (если поле времени есть) | перцентили времени по группам | medium | both |
| Мобильный против десктопного Googlebot: доля | UA-варианты | info | google |

## Чего не делать

- Не верить User-Agent без проверки DNS или диапазонов IP.
- Не печатать IP-адреса и параметры запросов с персональными данными в отчёт.
- Не делать вывод «бот не ходит» по логу origin за CDN без оговорки.
- Не загружать гигабайтные логи в память и не запускать параллельные DNS-запросы тысячами: уникальные IP, пауза, кэш ответов.
- Не блокировать подтверждённых поисковых ботов ради снижения нагрузки без согласия владельца.
- Не пересылать логи в сторонние сервисы.

## Выход

Находки по `templates/finding.schema.json`, `module: "logs"`. Плюс сводка: окно лога и ограничения (CDN, ротация, нераспознанные строки); таблица ботов (заявлено / подтверждено / не подтверждено, хиты, доля 2xx/3xx/4xx/5xx); распределение обхода по группам URL против матрицы индексации; топ проблемных путей без персональных данных.
